# 操作指南

工程师通过同一操作台完成 **原生工程上传 → 七阶段执行 → 验证结果 → URDF / MJCF 预览与 PR**。仓库、凭据、规格库和传输由平台维护，操作时无需输入服务器路径或流水线配置。

## 准备与提交

按[机械规范](mechanical-handoff-spec.md)确认工程范围、配置、实例、基准、运动、材料与受控参数。保存并收集完整原生目录，从收集目录重新打开主装配；变更后的原件版本须可取且不可覆盖。

通过飞书登录，选择本机工程文件夹。多个 `.SLDASM` 时明确选择主装配，一个时自动选择。确认配置的产品发布目标，选择用途（工程 `engineering` 或检查预览 `inspection_preview`；页面可预选工程用途，提交必须显式携带该选择），填写变更说明（必填，可多行），然后启动。文件/目录名称与范围限制在上传前显示，并由服务端复核；锁文件和非法输入必须先修正。

名称匹配只用于建议目标。CAD 已有产品标识优先且须与所选目标一致；提交身份不代替工程责任或批准。[系统契约](contracts.md#identity)定义其来源与内容身份。

批准租户内用户可提交并查看共享结果；发起人和明确配置的管理员可管理该运行。详情保留认证时的原始用户名，审计以稳定认证主体为准。

## 查看运行

页面按[七阶段契约](contracts.md#stages)展示输入、输入检查、输出与输出检查。失败首先显示对象、原因、证据与处理方向；测量结果同时给出单位和阈值，原始文件与摘要按需展开。

必需前提失败时，下游阻断，未执行检查不算通过。复用结果标明原生产运行和检查时间。警告保留对象和资格影响，可以与通过并存；零参数、未分配实例或材料缺失不能获得其对应工程资格。

原生活动显示当前操作、对象、实际可用计数与最后更新时间。计数只覆盖该操作，不表示全流程百分比或剩余时间。通信正常不能证明 CAD 正在推进，无新活动也不能证明作业已失败；页面区分确认状态与通信可用性。

生成后自动预览实际 URDF 与网格，显示绑定主体及当前质量报告；验证未通过时显著标注未验证，仅供诊断。验证通过后可检查关节方向、限位和接口，不能将视觉检查当作工程批准。不存在可安全读取模型时展示诊断，不预留空预览区域。

报告、页面、预览与 PR 显示同一用途、范围来源、参数缺失与资格。可读的原生/受控工程范围保持原值、按精确值使用。检查预览在转动关节范围经完整原生观察确证缺失时，使用 `inspection_rotation_full_turn/v1`（`[-π, π] rad`）；工程用途在完整原生观察确证没有启用机械范围且没有有效作者范围时，使用 `engineering_rotation_default_window/v1`（同为 `[-π, π] rad`）。两者都必须标注为默认/分析窗口而非机械限位，保留原始作者值及确证缺失证据；有效原生和作者范围优先，启用零范围不被默认覆盖。未知、缺字段、读取错误、无效证据或冲突均阻断，不进入默认窗口。缺失驱动按 `drive.missing_zero/v1` 输出零占位，并逐字段显示“平台默认占位，未建立驱动能力”；默认范围及默认驱动资格保持 `unqualified`，实机资格不由导出建立。

## 处理问题

| 结果 | 处理方向 |
|---|---|
| 原生打开、依赖或配置读取失败 | 核对具体原生错误、对象、字段与路径证据，区分来源缺陷和读取／环境问题；必要源修正另行形成受控新工程版本，不在采集中修改 CAD |
| CAD 行政属性缺失 | 按[系统契约](contracts.md#identity)保留缺项与来源；产品目标和必填提交说明建立行政 PR 身份，不代填工程修订、负责人或原件控制记录 |
| 缺少工程范围或驱动规格 | 可读范围保持原值、按精确值使用；检查预览采用 `inspection_rotation_full_turn/v1`，工程用途采用用户授权的 `engineering_rotation_default_window/v1`，两者均要求完整原生观察确证缺失且无读取错误，仅适用于转动关节、标注非机械限位并保持资格 `unqualified`；未知、无效或冲突仍阻断；移动关节缺少工程范围时保持缺项并阻断，不生成 ±π 范围；原始驱动缺项保留，输出按 `drive.missing_zero/v1` 填零并明确警告“平台默认占位，未建立驱动能力”；位置范围不得用零占位或冒充工程限位 |
| 已保存配置、结构或机械来源缺失 | 补充原生观察或工程依据；未知时保持诊断，不以填写行政属性替代 |
| 结构、轴线、基准或参数矛盾 | 根据具体证据修正原生定义或受控规格 |
| 不支持或读取能力不足 | 保留真实设计与诊断，由实现负责人修正读取/解释能力 |
| 外观无法忠实表达 | 保留 document/face、owner 配置与显示状态、同 state `GetRenderMaterialsCount2`/NULL、带 binding context 的持久引用索引、document QI、feature face footprint、纹理和读取错误；只有场景或总数证明无关的辅助事实可以忽略。未知实体、无法绑定的参与材质、冲突 owner 或无法消费的 present texture 使 Generate 与 Verify 明确失败，不输出默认色或挑选一层 |
| 材料缺失、未分配或零参数警告 | 评审其实际含义与用途影响，按需修正来源；不能删对象或调数清警告 |
| 独立验证失败 | 追溯原始证据与生成规则，保留失败产物与检查结果 |
| 通信中断 | 恢复连接并查询同一原生操作，不重复发起 CAD 工作 |
| 发布失败或结果未知 | 保留已验证交付与外部操作记录，恢复权限/服务后由发布阶段对账 |
| 发布基线变化 | 先对账原外部结果，再通过 Publish 阶段重跑建立新的不可变发布意图与实际基线；只有源工程变化才从 Freeze 重新建立结果 |

观察数量不是缺陷零件数量。一处未解析约束可能影响多个实例，应先判定问题来源。机械事实的变化在 CAD/规格中修正，形成新提交；不编辑模型、URDF、网格或质量报告。

## 恢复、重试与新建请求

阶段详情提供统一的 `Rerun <stage>`。七阶段均从已封存输入独立执行，默认只运行所选阶段；高级选项可明确延续到一个下游终点。新执行使用新的不可变请求和 command，保留原失败、产物与 producer。新结果需要继续验证或发布时，可从它再选择下一阶段，不借用失效的旧下游成功。

`Continue original job` 仅恢复同一已登记 command 的原执行，输入、tool、target 和 effect 身份不变。已有决定只核验返回原结果；不会换新工具改写终态。UNKNOWN 先对账原 operation，不能直接重发。已提交的阶段重跑若响应未知，界面锁定原正文和幂等键；刷新后仍对账同一请求。

首页首次上传提交新的受控原件，按 Freeze→Publish 完整运行。阶段重跑复用其真实依赖的封存前缀；Freeze 只复用 originals，Discover/Capture 才执行必要 CAD 工作，Generate/Verify/MJCF/Publish 不重复采集。工程原件或主装配变化从 Freeze 重新建立必要结果；规则、配置、用途和目标变化按实际影响重新核验，不把旧证书套到新事实。

单阶段范围成功只表示该范围完成。页面分别显示 Reused、实际执行及 Out of scope；正式交付仍要求完整有效来源、独立验证和本次 Publish 的真实 PR。所有权、原件、资格或外部结果不清楚时，界面显示具体原因并拒绝执行。

发起人和管理员可以请求取消尚未完成的运行。平台先停止自有操作并核对外部结果，确认后才显示取消；未决结果先对账，已完成发布不能被取消。取消保留请求、原始证据与诊断。

显示名用于识别运行，不影响工程身份。已结束记录可移入“已删除”并恢复；这是列表管理，不删除证据、作业或 PR。运行状态未知时禁止删除操作。

## 评审与用途验收

PR 绑定同一工程内容、工具、主体、报告与 commit。工程评审确认[自动覆盖之外的事实](mechanical-handoff-spec.md#review)与变化影响；已批准且仍适用的事实沿用，自动检查无需重复人工验算。

平台创建绑定所选用途的候选 PR（发布身份含 purpose）；工程负责人批准后再由模型发布流程集成与冻结。视觉模型、运动学、碰撞、动态仿真、训练与实机控制各有用途验收，不能以加载成功或 PR 存在代替。资格按 `(fact_id, scope, object_id)` 记录：模型一致性事实与 `engineering_position_range`、`drive_sizing`、`machine_qualification` 分别记录，前两项按关节定位，末项针对交付主体。工程批准与实机资格未建立不新增自动失败门，也不能被 PR 创建授予；不同用途的候选与发布恢复身份相互隔离。

历史手工 URDF 只用于隔离的参考单元测试与回归测试，不作为操作台阶段输入、验证真值、正式端到端或发布前置。测试只在 fixture 明确声明适用 CAD 原件、配置和修订时运行；不同版本须声明不适用或建立新 fixture，不能硬匹配旧 URDF。参考测试按拓扑、几何、方向、限位和运动语义及有依据容差分类，不比较 XML／STL 字节、元素或三角形顺序及合法三角化；参考通过或差异都不能替代当前 CAD 的独立工程验证。

## 独立复核

维护人员在配置了同一 `StageApplication` 的 Linux 环境复核已登记的 Verify 命令：

```sh
description stage <verify-command-id>
```

该命令执行已登记的正式 Verify 阶段。尚无决定时，它取得执行权，从原始证据运行验证，
并提交正式 decision、certificate 与 receipt；结果按既有契约参与后续发布。已有决定时，
命令只核验并返回原封存结果，不重新计算。Verify 对输入证据的读取不改写原件，但阶段
执行会写入业务事实。真正隔离复算须绑定既有 `DiagnosticReplayScope` 并走受控诊断
入口，不登记正式资格；不能把正式命令当作只读诊断。发布恢复使用操作台的 Publish 阶段重跑，
以保持同一授权、目标和审计流程。命令与完整交付边界见[交付契约](contracts.md#delivery)。
