# SolidWorks 机械交付规范

结构组交付完整、已保存、可重新打开的 SolidWorks 原生工程。流水线生成采集计划、模型、证据、URDF、网格、报告与 PR；工程师不编写流水线 YAML，不手工导出模型，不修改生成物。

“必须”和“须”表示必需项。CAD 提供工程事实，允许采用明确规则进行规范化、计算和有依据的修正。规则须绑定本次原生对象与读数，保留原值、结果和依据，并由独立验证复算。不得从手工导出取得名称、轴向、限位或网格，也不得为匹配手工结果加入特例。历史手工 URDF 只作为独立参考单元测试和回归测试 fixture，不进入生产或发布必经链。所有非原生直接读取的值按[来源警告契约](contracts.md#value-provenance)显示 warning。

## 可复现的导出流程

手工导出的经验按“当前原生读数 → 对象和配置绑定 → 规则及适用条件 → 输出字段 → 独立复算”提炼。历史文件、模型专用脚本和操作成功记录只提供调查与测试证据；每项规则须重新证明对当前输入成立。生成成功、保存状态一致、完整机械资格和硬件资格分别报告。

| 阶段 | 必须能从封存输入独立复现的内容 |
|---|---|
| Freeze | 原件清单、字节摘要、主装配和不可变请求；请求参数不补造 CAD 工程值 |
| Discover | 当前配置、原生依赖和实例身份、声明及配合读数、缺失和冲突、所需采集计划 |
| Capture | 计划对应的实际对象、几何、轴、物性和外观原值，以及读取范围和资源归还证据 |
| Generate | Linux 从原始事实按版本化规则生成唯一工程模型、URDF 和网格，逐字段记录派生依据 |
| Verify | 独立读取原始事实与实际交付字节，复算归属、坐标、轴、范围、几何、物性、外观及警告 |
| Publish | 发布已验证的同一内容，报告、预览、来源警告和 PR 绑定同一输入与输出身份 |

Windows 只执行对应阶段必要的原生读取和会话管理。原生对象按实际接口调用，参数化属性与方法、空返回、明确缺失、读取失败和不适用须分别记录。不能把所有配合强制转换为同一接口，不能把未知关系当作不存在或刚性连接。保全的部分读数是否足以交付，由 Linux 和独立验证依据其对输出的实际作用判定；必要事实缺失仍失败。

原生读取失稳时保全首读、后续读数、配置、对象集合、位姿和原件身份，以已有工程判据判断；不得挑选接近期望值的读数、分配残差、缩放质量或改阈值求通过。生产流程复用阶段内的有界读取机制，不增加针对某个模型的补读脚本、隐藏前置操作或第二条生成链。

生产代码和配置不得包含模型专用名称表、文件路径、日期、对象数量、关节表、参数或历史产物摘要来决定工程结果；名称相似、文件同名和遍历顺序不能证明对象绑定。正式 API 的接口标识、枚举、单位换算和公开版本化规则可作为通用常量。规则适用条件来自当前原生事实；更换模型名、实例名、目录或顺序后，符合条件的相同工程事实仍应得到等价结果。缺失外观、驱动或限位不能用展示默认值冒充已建立的工程能力。

参考回归须同时覆盖通用正例和反例：同名不同对象、跨配置或跨作用域、重复绑定、未知接口、部分读取、改变顺序、轴向重表达、范围启用状态、材料覆盖与物理不闭合。独立验证不得信任生成器的映射或成功标记；历史导出只在外部测试侧比较已生成结果。

## 交付范围与身份

每次交付明确主装配、一个已保存的交付配置、整机或模块边界，以及附件、负载、电机、减速器、紧固件、线束和简化件的纳入范围。范围须对应预期实物和所选用途；冻结请求记录提交时选择的用途（`engineering` 或 `inspection_preview`），用途不改变原生事实。

检查预览使用相同 CAD 来源与规则。允许有据的单位、坐标和方向转换；机械范围与分析窗口分别记录，窗口不能冒充机械限位。真实启用的零范围保留，未知状态不能当作无范围。驱动原始缺失保持可追溯；模型与 URDF 对缺失的 `effort`／`velocity` 按 `drive.missing_zero/v1` 写入 `0`，逐字段警告“平台默认占位，未建立驱动能力”，不标为 CAD 原生值。

产品标识稳定对应硬件，使用 1–64 个 ASCII 字符，以字母开头，其余为字母、数字、`_`、`.` 或 `-`。已有工程修订、原件控制记录、结构负责人和变更说明保留在 CAD/PDM 中。文件名、修改时间、显示状态和“最新版本”等文字不能代替这些事实。

行政发布身份按[系统契约](contracts.md#identity)逐字段解析。CAD 缺少行政信息不阻断测量；工程修订、结构负责人及原件控制记录缺失时保留缺项，评审 PR 显著列明，不据此授予责任或批准资格。平台确认的产品目标、提交主体、上传索引与内容摘要不能代替这些工程事实。已有 CAD 产品标识必须与发布目标一致，必需机械证据和自动检查仍须完整。

### 原生属性与来源

平台版本化统一 CAD 模板及其字段契约。文档级与配置级属性须无冲突；配置专属值适用于交付配置。使用 `dp` 命名空间：

| 属性 | 含义 |
|---|---|
| `dp.hardware_id` | 已有稳定产品标识 |
| `dp.revision` | 已有工程修订标签 |
| `dp.owner` | 已记录的结构负责人 |
| `dp.change_summary` | 本版工程变更或首版范围 |
| `dp.control.system`、`dp.control.reference` | 原件控制系统及可重新取得的固定记录 |
| `dp.delivery_configuration` | 明确指定已保存交付配置；属性省略时须由原生记录证明保存配置，存在时须与实际配置一致，未知或冲突拒绝 |
| `dp.robot_name` | 顶层装配的原生模型名；确证缺失时仅可按[固定命名规则](contracts.md#naming)格式化原生顶层装配名，行政登记和发布目标不补齐内部名称 |

工程修订之间的衔接由受控工程变更记录表达，发布的 commit/主体衔接由平台负责，不要求工程师维护流水线分支状态。

配合推导模式的关节属性保存在主装配中，`<name>` 与关节名一致：

| 属性 | 含义 |
|---|---|
| `dp.joint.<name>.axis_sign` | 当原生几何轴不带运动正向时提供 CAD 作者方向声明，值为 `1` 或 `-1`；绑定原生轴和运动定义，不能从历史导出反填 |
| `dp.joint.<name>.type` | 需要声明连续运动时填写 `continuous`；不得覆盖实际自由度 |
| `dp.body_datum` | 组件文档中用于消除所属刚体基准歧义的原生引用；重复实例仍须按装配上下文解析 |

受控配置和记录可以承载规则及来源，格式或存储位置本身不决定有效性。规则必须说明适用的 CAD 对象特征、条件、转换和输出含义，保留版本与摘要；派生对象映射可保存作复核证据。不得以记录文件为媒介抄入手工导出值，也不能通过回写 CAD 隐藏其来源。

参数责任人负责 CAD 内工程定义的真实性与适用工况。范围、输出侧驱动和可选独立预算均须保留原生对象、配置、单位及明确读数；读取不到时如实缺失，不由平台编造。

## 名称与原生引用

物料号标识可复用制造件，实例标识一次安装，模型接口名标识机械语义，三者分别管理。同一文件安装多次时，以完整装配路径、文档和引用配置区分，例如 `left_arm/output_shaft_01` 与 `right_arm/output_shaft_01`；不得按文件名合并。

文件名和工程显示名可以使用中文；现有 CAD 名称不规范时，流水线保留原名并 warning，按明确规则自动规范化，不因这一项阻断。最终模型名、刚体、关节、附加接口及其他输出名采用小写 ASCII snake_case，匹配 `^[a-z][a-z0-9_]*$`，名称稳定且唯一。不能用大小写、特征顺序或随机补号消歧；完整处理见[输入命名警告与输出一致性](contracts.md#输入命名警告与输出一致性)。

| 对象 | 名称规则与原生载体 |
|---|---|
| 根刚体 | `base_link`，基准 `CS_base_link` |
| 其他刚体 | `<位置或模块>_<物理部件>_link`，基准 `CS_<link>` |
| 运动关节 | `<位置或模块>_<区域>_<功能>_joint`；可选基准 `JCS_<joint>` |
| 固定关节 | `{parent}_to_{child}_joint` 或 `{component}_mount_joint`，两端引用规范 link 名 |
| visual / collision / material / mesh | 按所属对象及稳定原生身份派生命名，规则和引用闭合见系统契约；不得复制手工文件名或按遍历顺序编号 |
| 命名轴 | `AX_<joint>` 或原生声明明确引用的轴名 |
| 安装 / 工具 / 测量 | 接口后缀 `_mount` / `_tcp` / `_optical` 或 `_frame`；载体 `CS_` / `TCP_` / `SCS_` |
| 配合 | `<joint>__<约束作用>[_<固定序号>]`，如 `left_elbow_pitch_joint__coaxial` |

关节名称不要求与子刚体同名。`roll`、`pitch`、`yaw` 描述机械参考姿态中的运动功能，不能用于猜测实际轴线或正方向。中心结构省略左右；安装位置使用完整 `left/right/front/rear/upper/lower`，左右以机器人自身视角定义。

统一词根：

| 结构 | 词根 |
|---|---|
| 中心 | 躯干 `torso`、胸部 `chest`、骨盆 `pelvis`、头部 `head` |
| 模块 | 上肢 `arm`、下肢 `leg` |
| 上肢部件 | 上臂 `upper_arm`、前臂 `forearm`、手 `hand`、手掌 `palm` |
| 手指 | `thumb`、`index_finger`、`middle_finger`、`ring_finger`、`little_finger`；指节 `proximal/middle/distal` |
| 下肢部件 | 大腿 `thigh`、小腿 `shank`、足 `foot`；足底接口 `sole` |
| 关节区域 | `neck`、`waist`、`shoulder`、`elbow`、`wrist`、`hip`、`knee`、`ankle` |
| 移动与末端 | `chassis`、`wheel`、`caster`、`gripper`、`tool_flange`、`tool` |

一般机械部件按真实功能命名，例如 `housing`、`bracket`、`output_shaft`、`bearing`、`motor`、`reducer`。其他机构确认词根后沿用，不强行套用人体术语。

原生前缀标识载体，后缀完整保留接口名。共享零件中的局部基准不绑定单一安装侧；在所属装配中按实际实例命名左右或多处接口，引用原有定位特征，不为命名复制制造件。

首版确认所有接口的含义与绑定。已发布接口的改名、替换、拆分、合并及连接变化必须形成受控工程变更，说明消费者影响与对象对应关系。纯文件显示名变化不改变接口，名称相同也不能单独证明跨版本对象相同。

### 保存的原生命名基准与检查预览

当 CAD 明确没有保存的 exporter 声明，且冻结用途为 `inspection_preview` 时，`inspection_saved_native_carrier/v1` 允许从原生 `c_<semantic>` 坐标系与 `a_<semantic>` 参考轴建立检查模型。它使用同一七阶段与工程模型，不将历史导出或辅助生成日志作为输入，也不把预览声明提升为机械或硬件资格。

- 组件归属来自完整原生实例层级。装配容器须有直接子实例，其定义文档、配置及作用域与父实例精确一致，并具有成功读取的原生 `IComponent2.Solving=0`；文件后缀和零件返回的数值 `0` 单独不足以声明刚体。柔性、未知或冲突不折叠。
- 唯一保存的顶层固定实例与 `c_base_link`／`a_base_link` 声明检查模型的根；不声称 `IsFixed` 或不完整配合已经证明六约束附着。其余载体须由成功读取、端点精确绑定且未锁转的同心接口形成完整无环树。
- 坐标系与轴须成对、作用域和配置一致、有限且不退化，坐标原点位于对应轴线上。每条接口的两个原生端点必须与候选轴线一致。原生语义名只能筛选已具有几何证据的候选；剩余绑定须整体唯一。缺项、重复、无匹配、多解及跨拓扑冲突均拒绝，不能靠名称、编号或遍历顺序猜测归属。
- `IMateEntity2.ReferenceType` 使用官方 `swMateEntityTypes_e`，与 `ReferenceType2` 分别保全。圆形边的通用 point／mate-vector 仅在同心接口中作为同时受到命名轴及另一端点约束的轴线证据，不伪作圆锥、圆柱实体或配合秩。
- 原生命名轴是无向直线。已有有效方向声明须保留；缺失时，`stored_endpoint_order/v1` 仅定义检查模型的展示方向，并逐对象警告正运动和硬件方向未建立。已有原生范围需要明确方向绑定；未知启用状态或读取失败不能套用默认窗口。确证没有范围时使用既有检查窗口；缺失驱动仍按 `drive.missing_zero/v1` 写入零占位并警告。受控记录、真实零范围及原生非零值不能被默认值覆盖。
- 其余保存姿态配合保留原生对象及字段定位、类型、端点和错误，不给未理解的约束补秩，也不冒称已证明实际自由度。报告、模型、URDF、预览和 PR 一致显示声明、方向及资格警告；Verify 从原始证据独立重建绑定及警告，不能信任 Source 的映射或成功标记。

## 文件、配置与保存状态

一次交付是自包含工程文件夹，保留主装配、实际依赖的子装配/零件、工程图、自定义材料库、设计表及其他影响交付的来源。

- 使用 Pack and Go 或等效方法收集，从收集目录重开并完全解析交付配置，不依赖原目录、个人路径或共享盘。
- 内嵌虚拟组件可由已封存的所属装配提供几何，须以直接原生读取证明 `IsVirtual=True`、所属装配字节、实例、引用配置及当前受控会话中的 `VC~~` 文档归属；临时路径或虚拟标记单独出现不足以准入。不把临时文档当作上传来源，也不将其混同为 `IC~~` 导入缓存。不能建立完整绑定时拒绝采集。重复实例的全部引用配置保持有效。
- 外部设计表、方程及上下文依赖须内嵌、收集或固化为可重新读取的受控原生结果。
- 采集接纳已保存的普通文档、有完整证明的内嵌虚拟组件，以及由封存所属装配在 Capture 新受控会话中重现的 `IC~~` 导入物化。后者必须同时绑定冻结所属装配字节、完整实例路径、所属锚点、引用配置和原生 API，且 `IsVirtual=False`；每个会话分别核验当次 PID、`swxPID/IC~~` 路径和归属，临时路径或 PID 不作为跨会话身份。只向 Capture 传递实例与稳定身份摘要，不复制或复用旧缓存。作者导入路径及读取错误保留；包内精确来源核对冻结字节，现存包外来源或冲突拒绝，无法取得原始导入来源时明确警告源完整性未建立。来源 scope、模型、URDF、报告、预览与 PR 保留同一警告；独立 Verify 复算稳定身份并分别核验两次会话证据。普通文档的导入历史或名称不构成拒绝依据。
- 不包含符号链接、junction、`.git`、大小写冲突、Windows 保留名称、非法字符、以空格/句点结尾的名称或 `~$` 锁文件。
- 不将流水线生成的定义、交付清单、URDF 和网格作为工程输入。

主装配及依赖以已保存原件交付，在发行物列明的受支持 SolidWorks 版本中只读打开，一次读取原生几何、轴线、配合、物性及对应对象、配置和位姿。实际参与读取的对象和原件必须可绑定，原件摘要始终不变；真实缺失、冲突和读取失败原样保留。辅助状态不触发 CAD 修改，也不替代所需原生读数的验证；坐标转换、模型生成和工程复算在释放 CAD 后离线完成。

配置明确附件、负载、抑制与引用配置。隐藏只改变显示，不能定义物理排除。展示、运输或临时装配姿态不能自动当作机械零位。发生工程变化须形成新的原件版本，原交付保持可取且不被覆盖。

封存原件在原生读取前后核对完整字节身份，不执行 CAD 重建、保存或修复。原生读取位置与封存原件保留完整绑定，不能冒充未变的原件。满足前述内嵌来源绑定要求的虚拟组件无需另存；若为解决无法绑定的来源而另存虚拟件、固化依赖或修正配置，这些工程准备须在冻结前完成并交付新版本。

导入来源证明同时保留引擎报告的来源/依赖路径、原生所有者与实例身份及包内来源摘要；验收须在原目录不可用且未借用缓存时重新解析。

平台在 Windows 原生解析后核验实际读取来源。已知缺失引用允许带详细警告继续导出可读取的保存状态，明确源完整性未证明及隐藏对象未知；不要求参数化重建或修改原件。未授权包外来源、纳入对象的未知绑定或必需数据不可读仍拒绝；完整执行边界见[架构设计](design.md)。读取能力限制须与工程错误区分，不能要求工程师删除真实结构来迁就读取器。

## 刚体、拓扑与机械解释

刚体是运动中内部相对位姿不变的实例集合。子装配层级、临时固定、零位时静止或配合名称本身不能证明刚性。子装配包含运动时保留正确的柔性状态；多实体内部相对运动应表达为可分别定位的原生实例。

先建立当前配置的“实例 → 有据的刚体 → 原生关节两端”映射，再选择根和父子连接。依据包含完整配合端点、抑制与错误状态、约束剩余自由度，以及刚性/柔性子装配和跨装配配合的求解语义。约束状态按实际 API 版本解释；`IsFixed` 只说明装配固定锚点，`false` 不等于未连接，局部欠约束也须结合预期运动判定。多个同轴对象由原生引用消歧，轴线重合本身不确定连接两端。

参考会话的模型专用资料只用于隔离测试与历史调查。参考测试须成对固定原生 CAD 输入与手工期望输出；切换时同时切换两者。配套 CAD 通过正常 Freeze 作为本次测试请求的原生输入，不能把 fixture 作为生产实现或固定配置。手工导出不进入任何生产阶段，不提供当前接口名、方向、归属、连接或数值真值，也不参与放行。参考测试只在 fixture 声明兼容的 CAD 原件、配置和修订上运行，按工程语义和有依据容差比较，不锁 XML／STL 字节、元素或三角形顺序或合法三角化；版本不同不得硬匹配旧 URDF。局部约束秩或保存姿态下的刚性证明只适用于其对象、配置和姿态，不能外推为完整机构自由度资格。

模型以唯一 `base_link` 为根，支持固定、有限转动、连续转动和直线运动的树状连接。真实闭环、并联、齿轮、螺旋、耦合及其他多自由度关系不属于该模型表达范围，须保留真实设计，由平台明确报告不支持，不能通过删杆、解耦或固定被动件伪装。

存在有效的 `URDF Export Configuration (v1.4)` 原生声明时，按持久组件身份展开连杆选择，读取名称、拓扑、命名基准、轴线及作者限位，并与原生观察核对。网格、惯量与非自定义原点重新从 CAD 取得；声明中的导出缓存不是工程证据。原生声明必须直接读取并绑定当前 CAD 对象；手工导出文件及其回写副本不因存放在 CAD 中就成为有效工程来源。仅固定保存姿态的配合限制作为诊断，可比较的工作限位冲突仍失败。存在但无效或不可读的声明不能回退到配合推导。

原生 `MateInPlace` 通过 `IMateInPlace` 独立采集，保留组件、索引实体类型、组件名称、原生空返回和逐字段读取错误；实体可以是参考平面，不冒充普通 `IMateEntity2`。它不提供普通配合约束行、关节类型或工作限位。仅当实际拥有范围的所有材料叶实例已完整归入同一个原生声明连杆、求解错误为零、已读组件身份与配置不冲突时，允许警告后继续保存状态导出；跨连杆、未分配或未知拥有范围仍阻断。Source 与独立 Verify 分别核对归属，模型、URDF、报告、预览及 PR 保留同一原始观察警告。该处理不证明完整机构约束或机械资格。

确证声明不存在时，按完整配合集合重建刚性和相对运动。支持重合、同轴、距离、平行、垂直、角度、锁定及相应限位；组合须明确消除刚体内部六个自由度，或在相邻刚体间只保留一个受支持运动自由度。`IsFixed`、单个配合及命名均不能代替该证明。

所有纳入实例恰属一个刚体，不重复计入。声明允许留下显式未分配实例，但必须保留其原生身份及独立物理读数，参加整机核算；该候选不获得整机 URDF 覆盖资格。不能删除实例、臆造附着或缩放质量来消除警告。

两种机械解释均须核对逐件运动：在有据的非零单关节和关联组合姿态下，每个纳入叶实例按其原生刚性归属跟随，组内相对变换保持不变，接口连接连续。静态几何和物理闭合不能代替该核对；检查范围与资格遵循[质量规范](quality.md#gates)。

## 轴线、基准、零位与正向

每个最终刚体有固定于自身的原生 `CS_<link>`，根使用 `CS_base_link`。复用真实定位基准，不新增有质量的辅助几何。基准必须能通过文档、实例、配置和原生身份重新取得。

根基准采用右手系，X 向前、Y 向左、Z 向上；无自然前向的设备以 CAD 原生安装定义确认。原点采用真实定位基准，不默认为装配原点、包围盒中心或 COM。

主装配中的 `CS_base_link` 仅在涉及装配基准的约束共同消除六个自由度并唯一连接根刚体时可归属根；坐标重合和临时固定不构成证明。不能明确证明的装配基准归属保留诊断。

配合推导的关节基准采用子刚体基准，原点在真实运动轴上；可选 `JCS_<joint>` 须同属该刚体且与子刚体基准一致。显式原生声明保留其自定义关节基准和相对变换，仍须绑定真实对象并通过原生几何核对。安装、TCP 与传感器基准可以有独立偏置，归属明确。

轴线必须来自正确实例中的可独立重读参考轴或圆柱接口。声明路径绑定命名参考轴，配合推导路径绑定圆柱面。圆边可参与同轴或共面配合解释，但不能单独代替关节轴的重读依据。远处平行特征、序列化方向数字和截图不能作为轴线证据。

关节原点须由完整定位确定，轴线不足以确定沿轴位置。保留真实相交、偏置及异面关系，不套用几何中心。基准三轴正交、单位化且右手，镜像实例也须满足。方向规范必须声明机械参考系和正运动语义；roll／pitch／yaw 的默认 +X／+Y／+Z 不能与任意局部 frame 的分量混用，斜轴保持真实轴线。名称只用于语义分类，不能单独决定物理轴向。

交付配置绑定机械零位与正方向。转动遵循右手定则，直线沿有向轴；参考姿态不是零位时必须有可读取偏置。工程师确认实物意义，平台完成单位和坐标变换，无须手写 XYZ/RPY 或轴向向量。

坐标基准变化时，将轴线与正方向变换到同一个有据的工程参考系比较，保持物理方向。局部轴分量或参考轴端点顺序相同不能单独证明正方向一致，也不能建立电机、编码器或控制通道的符号资格。

CAD 方向表达偏离规范时给出明确 warning，按 CAD 运动关系和统一规则纠正导出结果；可修正的规范偏差不单独阻断。警告列明原始方向、规则、规范方向和影响字段，原始 CAD 保留。轴、基准、零位、限位及运动验证须保持一致；仅翻转轴向而不处理相关语义不合格。具体规则与独立验证见[系统契约](contracts.md#原生交换协议)。

## 工作范围、驱动与安全

工作范围以当前 CAD 的有效作者定义和原生限位为依据，允许按照明确规则换算单位、重表达坐标及同步变换上下界。规则处理不覆盖真实限位、不把普通配合尺寸冒充工作范围。分析窗口和机械范围分别标明来源与资格；手工结果不得补值。可比较原生来源有冲突时保留失败诊断，不以优先级掩盖。

每个运动副的工作范围适用于本版配置、零位、正向与工况。明确连续运动须真实成立，线缆回卷、止挡或禁行区不能被忽略。可比较来源必须一致。

驱动规格明确电机、传动及输出侧，区分持续/峰值、持续时间、负载、温度与工作制。电机 rpm、电流和电机轴力矩不能直接作为关节输出能力。参数责任人确认换算、效率及适用条件，平台核对 CAD 原生来源与数值一致性。

原生作者的零范围、零 effort/velocity 如实保留并警告，不能当作可用运动或驱动能力。缺失位置范围按用途契约处理；缺失驱动参数仅采用用户授权的零占位规则，保留原始缺项和未建立资格。读取失败、无效或冲突不能当作缺失。

派生模型使用 m、rad、kg、rad/s 或 m/s、N·m 或 N、kg·m²。原生及规格可用其他明确单位，由平台一次转换；不能缩放网格或重复换算修补输入错误。

工程验收必须覆盖参考姿态、端点及关键组合姿态，检查全行程干涉、间隙、公差、止挡、线缆/软管、附件与负载。设计接触、过盈或简模重叠须有对象、原因与适用范围。离散抽样和理想 CAD 无重叠不能单独证明实物全行程安全。

## 几何与物理事实

## 自动检查与工程责任

自动检查通过即采信，无须重复手算或签字；必需检查失败必须修正，不能人工豁免。具体检查、数值判据及资格由[质量规范](quality.md)唯一规定。

| 工程责任 | 需确认的外部事实 |
|---|---|
| 结构负责人 | CAD 与预期实物、配置、刚性/自由度、接口身份、零位、正向及工程变更对应 |
| 机械安全责任人 | 全行程、关键组合、干涉、间隙、公差、安全余量与线缆约束 |
| 参数责任人 | 输出侧规格、传动、持续/峰值工况及适用条件 |
| 物理参数责任人 | 真实材料、密度、物理范围、覆盖与简化来源 |
| 预算责任人 | 已提供预算的独立性、范围和不确定度 |

批准留在绑定内容身份与交付主体的 PR 或受控记录中。仍适用的已批准事实可沿用，仅评审变化及影响；平台不推断外部审批状态。模型加载、运动一致性、仿真、训练与实机控制分别验收。

发现运动或归属异常时，先绑定当前来源、配置和完整实例路径，记录驱动方向及复现姿态，取得配合端点与求解依据后分类：

| 分类 | 修正要求 |
|---|---|
| 导出或验证违反一致的原生依据 | 保持 CAD 原件，修正对应的实例映射、连接或坐标转换；拓扑变化从当前原生世界变换重新计算相对原点 |
| 原生依据证明 CAD 违反预期工程运动 | 保留原始版本，在版本化副本按工程依据修正具体配合或求解模式，重新采集并绑定新内容身份 |
| 来源不可读、依据缺失或相互冲突 | 保留未决诊断，补充读取或工程定义；不猜测附着，不授予机械资格 |

反馈包含主装配与配置、完整受影响实例、来源摘要、驱动关节及带方向和单位的复现姿态、相对哪个对象未随动、原生见证、准确操作及理由、前后检查和复发反例。CAD 修正还须列出原版本与新副本身份、具体配合端点或求解模式变更，以及保留所需自由度的理由；不能以全部固定消除症状。修正涉及的来源、模型、检查、预览与 PR 绑定同一身份；仅修连接时核对零位几何、网格和物理读数保持不变。具体流程见[操作指南](operations.md)。
