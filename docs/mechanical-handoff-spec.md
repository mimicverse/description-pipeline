# 结构组交付规范

本规范定义结构组向 `solidworks-to-urdf` 流水线交付的 CAD、机器人机械定义和证据。结构组交付一个自包含目录，使相同输入能够被重新读取、独立核对，并生成可追溯的 URDF。

输入合同为 `solidworks-to-urdf.input/v1`，CAD 版本合同为 `solidworks-to-urdf.cad-revision/v1`。本文适用于树形机构的 SolidWorks 原生交付；当前原生受测平台为 SolidWorks 2026，主版本号 34。其他版本须另行验收。

本文中的“必须”是交付要求，“建议”是推荐做法。机械定义正确性由结构评审确认；当前自动检查的覆盖范围见[第 11 节](#11-验收与实现边界)。规范要求不等于系统已经能够自动证明该要求。

结构组交付一份符合本规范的目录。统一操作入口的设计为只接收该目录路径；仓库、分支、执行节点和运行编号由平台管理。本文规定目录中的机械事实，不要求结构人员填写部署参数。入口的可用状态见[操作手册](operations.md)。

阅读顺序：先按第 2～8 节准备 CAD、基准、关节和证据，再按第 9 节填写唯一的 `robot.yaml`，最后按第 10 节完成逐项交付评审。第 11 节说明自动验算与人工评审的边界，第 12 节列出常见不合格项。

## 1. 交付内容与责任

### 1.1 三类输入

| 输入 | 结构组负责的内容 | 系统处理 |
|---|---|---|
| 原生 CAD | 保存后的装配、依赖、配置、几何基准和物理材料 | 读取几何、装配变换、坐标系、质量、质心和惯量 |
| `robot.yaml` | 刚体归属、关节关系、轴向正负、限位、证据绑定和验收范围 | 解析机械语义，生成规范模型和 URDF |
| 版本与证据 | 结构版本、来源记录、参数依据和评审结论 | 生成文件摘要、封存版本并绑定交付报告 |

CAD 定义几何事实，`robot.yaml` 定义机器人机械语义，规格与实测定义相应参数的依据。同一事实不得同时在多处维护。例如，关节原点来自 CAD 坐标系，不再手填一份 XYZ/RPY。

### 1.2 责任边界

结构负责人确认装配配置、刚体划分、几何基准、关节零位和方向。参数责任人确认质量、速度、力矩或推力的来源及适用条件。机械评审人确认输入含义和例外；负责人署名不能代替评审结论。

平台维护者负责工具、Windows 执行环境、Airflow 连接、仓库和分支配置。结构组不维护运行 UUID、连接令牌或 GitHub 凭据，也不通过修改生成的 URDF、网格或惯量修复问题。运行和部署分别见[操作手册](operations.md)与[部署说明](deployment.md)。

## 2. 目录、文件与版本

### 2.1 自包含交付目录

```text
arm/r1/
  robot.yaml                  # 唯一 YAML 机械定义
  cad-revision.json           # 工具生成的 CAD 版本清单
  cad/
    robot.SLDASM              # 本次交付的总装
    base.SLDPRT
    arm.SLDPRT
    subassemblies/            # 实际使用的子装配与零件，可保留原有层级
  evidence/
    mechanical-review.md      # 机械定义、基准说明、姿态依据与评审记录
    limits.txt                # 关节限位、速度、力矩或推力依据
    masses.txt                # 使用规格或实测质量时必需
    drawings/                 # 本次适用的图纸、规格书和测量附件
```

目录名称示例不限定机型或版本命名。`robot.yaml` 和 `cad-revision.json` 的文件名固定；`cad/` 与 `evidence/` 是推荐组织方式，其内部名称可按实际工程安排。交付单位是整个目录，不是单独的总装、YAML 或 URDF。目录内部路径始终使用包内相对路径；统一入口支持的外部目录位置见操作手册。

本规范以总装 `.SLDASM` 为交付入口。单刚体也通过总装组织，并使用 `joints: []`。采用 Pack and Go 或等效方式收集依赖，随后在交付目录中重新打开指定配置，确认其不再依赖原工程目录、共享盘或个人电脑上的其他文件。

### 2.2 文件规则

- 配置中的文件路径使用包内相对路径和 `/`，例如 `cad/3.0 总装.SLDASM`。支持中文名称；禁止绝对路径、`..` 越界、符号链接和 Windows junction。
- 文件和目录名称不能仅靠大小写区分。禁止在同一交付包中出现 `Arm.SLDPRT` 与 `arm.SLDPRT` 等歧义。
- 包内路径不得包含 `.git`、Windows 保留名称（如 `CON`、`NUL`、`COM1`，带扩展名也不允许）、控制字符、`< > : " \\ | ? *` 或以空格、句点结尾的名称；不能把不兼容的命名留给 Windows 执行端临时修改。应在实际 Windows 执行路径中验证目录深度和名称长度可被 SolidWorks 打开。
- 包内只保留一份 YAML，即根目录的 `robot.yaml`；不得加入其他 `.yaml` 或 `.yml` 配置。评审与说明使用 Markdown、文本、PDF 或其他适合的附件。
- 对指定配置完成强制重建（Force Rebuild），消除重建错误，保存总装及全部引用文档后再交付。未保存的桌面修改不属于交付输入。SolidWorks 的 `~$` 锁文件由系统排除，不作为结构版本。
- YAML 不得有重复键、未知字段或非有限数值；不能用 `NaN`、无穷大、空值或占位符代替必填参数。
- 输入包与生成输出、模型仓库、运行状态目录分开存放。封存后停止修改 CAD，排队和采集期间也不得修改机械定义或证据。

原始输入被完整归档；采集使用单独收集、重定位的 CAD 副本，不保存覆盖原件。

### 2.3 CAD 版本信息

结构组提供以下事实，封存工具据此生成 `cad-revision.json`。文件清单和 SHA-256 由工具计算，不得手工编造或修改。

| 字段 | 定义 |
|---|---|
| `hardware_id` | 稳定硬件标识，必须与 `robot.yaml` 相同 |
| `revision` | 当前结构版本标识，不超过 64 个 ASCII 字符，以字母开头，其余为字母、数字、`_`、`.`、`-` |
| `parent_revision` | 前一结构版本，标识规则同 `revision`；首次交付为 `null`，不得指向自身 |
| `owner` | 可追溯的结构负责人 |
| `change_summary` | 本次变更内容，以及受影响的接口、关节、基准或参数 |
| `control.system` | `git`、`pdm` 或 `handoff` |
| `control.reference` | 可重新取得原件的受控记录；Git 必须包含完整提交摘要，PDM 或目录留存须有明确版本引用 |
| `cad_files` | 工具生成的所有包内原生 CAD 文件及其摘要 |

新结构版本的 `parent_revision` 应延续该模型评审分支上一份已提交交付；结构组负责确认版本链，发布阶段还会核对与已有交付的关系。静态检查确认标识合法且不指向自身，不核实外部 PDM 或目录留存的完整历史。

CAD 文件发生变化必须建立新版本，并保留前一版。不得给已使用的版本号换一套 CAD。仅修改 `robot.yaml` 或证据时，可以保留相同 CAD 版本；应保留前次完整输入交付，另存新的提交目录，避免覆盖评审依据。

目录留存是有效的版本方式，但必须能够重新取得该版本的原件。“桌面上的最新文件”或可被覆盖的路径不能独立充当版本依据。工具记录 Git/PDM 引用，不代替对外部来源系统的核实。

### 2.4 SolidWorks 交付前检查

结构负责人必须在收集后的副本中完成下表检查，不能只验证原工作目录能打开。

| 检查对象 | 交付要求 |
|---|---|
| 主装配 | 打开 `source.assembly` 指定的总装，切换准确的 `source.configuration`，完成强制重建并保存；不能留有重建错误 |
| 子装配与零件 | 所有纳入实例都有真实、已保存的 `.SLDASM` 或 `.SLDPRT` 文件；嵌入的虚拟对象须另存并纳入包内依赖 |
| 引用路径 | 在原工程目录不可用时仍能重新解析；不得依赖丢失文件后的交互查找、重定位提示或临时替代件 |
| 实例配置 | 列明每个零件实例实际引用的配置；同一文件的不同配置不能混读，不能默认读取文件当前活动配置 |
| 轻量与未解析状态 | 应交付的零件可完全解析，能够读取实体、质量属性和参考特征；不能以轻量显示成功代替原生可读性 |
| 抑制与隐藏 | 抑制对象、原因和适用配置明确；隐藏仅影响显示，不能作为从质量或刚体归属中排除对象的方式 |
| 空装配与缺失实体 | 纳入的叶级对象是实际零件；空子装配、无几何占位件和无法读取的实体须在交付前处理 |
| 多实体零件 | 列明纳入的实体及其有效材料；若内部实体应分别运动，必须重组为可明确归属的原生零件实例 |
| 外部设计依据 | 设计表、关联设计或上下文引用影响本配置时，保存稳定的重建结果并归档对应版本依据；不得要求执行时再从个人环境取数 |
| 文件状态 | CAD 文档没有未保存的几何、配置或材料修改；不能要求采集程序替结构组保存设计变更 |
| 最终复核 | 重开交付副本，逐项核对配置、实例、基准与材料；将结果记入机械评审记录 |

采集程序会重建其只读副本以刷新原生缓存。该动作不是设计修复，也不能代替结构组确认配合、配置和零位的正确性。

## 3. 命名、身份与单位

### 3.1 名称与稳定身份

| 对象 | 规则与示例 |
|---|---|
| `hardware_id` | ASCII 标识，规则同结构版本；建议小写且与 `source.robot_name` 一致，例如 `arm` |
| 机器人 `robot_name` | 小写字母、数字和下划线，以字母开头，例如 `humanoid_arm` |
| 刚体 `id`、关节 `id` | 稳定的小写标识，例如 `left_wrist_roll`；不能因显示名称调整而随意更换 |
| 刚体 `name` | 唯一，建议以 `_link` 结尾，例如 `left_forearm_link`；唯一根刚体固定为 `base_link` |
| 关节 `name` | 唯一，建议以 `_joint` 结尾，例如 `left_wrist_roll_joint` |
| 附加坐标系 `name` | 唯一功能名称，例如 `tool_frame`、`imu_frame`、`camera_optical_frame` |
| CAD 坐标系名称 | 建议 `CS_` 加功能名称，例如 `CS_left_wrist_roll`；总装中的名称必须唯一，不能仅大小写不同 |
| CAD 零件与装配实例 | 保留工程名称与精确实例路径；中文可用，不能用显示简称替代实例身份 |

机器人实体名称采用单个下划线分隔单词，不使用空格、中文、连续下划线或末尾下划线。现有下游标准名称可以保留，但必须在机械评审清单中明确含义。字符格式、名称唯一性与部位语义是不同检查：格式通过不代表左右或关节功能命名正确。

左右以机器人自身视角定义，不以观察者视角定义。`roll`、`pitch`、`yaw` 应与已声明的机体方向和实际功能一致，不能只按 CAD 轴字母猜测。

`id` 用于连续追踪机械对象，`name` 用于 URDF 和下游接口，CAD 实例路径用于绑定真实零件。三者的对应关系须可追溯。改名、拆分、合并或左右互换必须在变更说明中记录。

同一 `.SLDPRT` 被装配多次时，每个实例都有独立身份，例如 `left_arm-1/wrist-1` 与 `right_arm-1/wrist-1`。实例路径来自顶层装配上下文中的 `IComponent2.Name2`，以实际原生采集清单为准；不能只抄零件文件名、自行拼接路径或按文件名去重。封存前须保留实例与引用文件、引用配置的对应清单。

### 3.2 单位

| 数量 | 机械定义中的单位 |
|---|---|
| 长度、直线行程、位置 | m |
| 质量 | kg |
| 角度、角行程 | rad |
| 转动速度、直线速度 | rad/s、m/s |
| 关节输出力矩、推力 | N·m、N |
| 惯量 | kg·m² |
| 时间 | s |

CAD 界面和原始图纸可以使用 mm、g、deg 等工程单位，证据必须保留原单位及换算说明。`robot.yaml` 和系统模型使用上述 SI 单位；不得通过缩放 URDF 网格补救错误单位。

## 4. 装配与刚体划分

### 4.1 指定装配状态

`source.assembly` 指向总装文件，`source.configuration` 填写准确配置名，包括实际中文名称。不能依赖“当前活动配置”。交付配置必须明确以下内容：

- 纳入和抑制的实例，以及抑制原因；展示配置、轻量表示或替代件不能隐藏应交付的运动件。
- 与机械零位对应的关节姿态，见[第 5 节](#5-坐标系与零位)。
- 影响质量、尺寸或运动接口的配置特征、材料和附件。
- 每个实例的引用文档和配置；引用必须可在交付包内重新解析。

结构评审应检查配合错误、重建错误、欠定义、过定义和非预期自由度。合法运动自由度与装配松散导致的自由度应分别记录；不得为了得到“完全定义”而锁死真实关节，也不得以 CAD 能打开代替装配正确性。

### 4.2 刚体定义

刚体是运动中内部零件相对位姿保持不变的集合。`bodies[].components` 必须逐项列出纳入的叶级零件实例；子装配名称不能代替该集合。

所有实际采集的实例必须恰好归属一个刚体，不得遗漏、重复或跨刚体占用。电机定子、转子、减速器输入和输出按真实连接关系归属，不能仅因属于同一个 CAD 子装配而合并。紧固件、线束等按模型适用的固定归属记录；存在相对运动的柔性对象须说明建模假设。

固定连接可以保留为两个刚体及一个固定关节。刚体融合会改变惯量组合和实体身份，必须记录合并关系，并由系统重新计算，不能手工相加惯量对角项。

每个刚体必须绑定独立、明确命名的 CAD 坐标系。可动子刚体坐标系兼作其入边关节坐标系；固定子刚体的坐标系按受控安装接口确定。附加工具或传感器基准使用 `source.frames`，不为其伪造有质量的刚体。

### 4.3 支持范围

v1 接受单根、连通、无环的关节树。每个非根刚体只有一个父关节，唯一根为 `base_link`。单刚体模型的关节列表为空。

关节类型仅限 `fixed`、`revolute`、`continuous`、`prismatic`；`planar`、`floating`、螺旋、齿轮联动或万向关节等不能作为新类型直接填写。

闭环、mimic 联动、机械耦合、柔性变形和其他不能由独立树形关节表达的关系，不得通过删杆、拆环或随意固定来掩盖。它们需要扩展合同和验证；v1 不授予相应能力。执行器、传感器驱动及控制配置也不属于本输入合同。

## 5. 坐标系与零位

### 5.1 每个基准必须定义什么

在 SolidWorks 中建立坐标系时，必须在 `evidence/mechanical-review.md` 或其引用的受控图纸中记录：

| 项目 | 必须明确的定义 |
|---|---|
| 所属对象 | 对应刚体、关节、工具或安装接口；相对哪个刚体固定 |
| 原点 | 指定 CAD 点、圆心、轴线与平面交点、安装面中心等可重建几何依据 |
| 轴线 | 指定确定轴方向的边、圆柱轴、基准线或其他受控特征 |
| 轴向正负 | X/Y/Z 分别指向什么；依据的观察方向或正向运动姿态 |
| 零位 | 保存的装配配置及姿态依据，避免“看起来摆正”这类描述 |
| 引用名称 | 与 `robot.yaml` 完全一致的 CAD 坐标系名称，以及定位特征 |
| 评审依据 | 图纸版本、关键尺寸、截图或姿态记录及确认人 |

原点定位必须确定三个方向的位置。只给转轴线不能确定沿轴位置；只给一个安装平面也不能确定面内位置。基准应由稳定机械特征建立，避免依赖临时选择、渲染外观或可随建模顺序改变的偶然面编号。

v1 按名称读取顶层总装文档中的坐标系。采集清单由 `bodies[].frame.coordinate_system` 和 `frames[].coordinate_system` 的实际引用派生，不另写 `coordinate_systems` 列表。只在零件内部建立同名坐标系，不代表总装端能够直接找到它；用于交付的基准必须以唯一名称在总装中可解析，并说明与所属零件的关系。原生读取找不到该名称时返回 `cad_missing_coordinate_system`。

建模时先切换并保存交付配置，用规定的机械特征建立定位点、基准轴或基准面，再通过 SolidWorks“插入 → 参考几何体 → 坐标系”选择原点及轴向依据。命名后在总装中显示三轴，逐一核对方向和所属对象，并保存文档。不能只保存一张坐标箭头截图而不保留可重新读取的 CAD 特征。

### 5.2 轴向与右手系

所有坐标系必须正交、单位化且右手：`X × Y = Z`。坐标变换只能包含旋转和平移，不能用缩放、镜像或非正交矩阵表达安装方向。左右零件的几何可以镜像，其坐标系仍须保持右手。

根坐标系采用机器人机体约定：X 向前、Y 向左、Z 向上；无天然前向的设备由受控安装图规定“前、左、上”。根原点由机型基准图确定，不默认取世界原点或质心。

关节坐标系不要求与根坐标系平行。应明确其三轴与安装几何的关系，并用 `joints[].axis` 表达正运动轴。不能因一条轴对齐便忽略另外两轴及其符号。

### 5.3 关节原点与机械零位

v1 用子刚体的 CAD 坐标系作为关节坐标系，关节变换由父、子刚体基准直接派生。结构组必须同时确定：

1. 真实运动轴线。
2. 轴线上采用哪个点作为原点，例如轴线与规定轴承中面或安装面的交点。
3. 子刚体在 `q = 0` 时的实际机械姿态和完整坐标方向。

不同机构不能一律使用“几何中心”。轴承中心、输出法兰中心、两轴交点或其他设计基准应按实际结构规定。沿轴移位可能仍保持等价转动运动学，但会改变接口基准，不能因此视为符合位置规范。

多轴机构应按真实几何处理：相交轴使用实际交点，异面轴或偏置轴保留设计偏置。不得为了坐标整齐而强行使多个腕轴共点，或把真实的非零间距写成零。

交付配置必须保存声明的零位。机械零位、编码器零位和上电回零位应分别说明；存在偏置时保留对应证据，不能靠改变导出坐标系掩盖。若定义的数学零位不在允许运动范围内，必须说明原因及可到达参考姿态，禁止把不可到达姿态当作实机验收姿态。

应提供零位图，以及每个可动关节单独正向运动后的参考姿态。对于腕部等紧邻多轴机构，应能逐轴辨认父子关系、原点、运动方向和末端变化；整体外观相似不能代替逐轴确认。

### 5.4 工具和传感器安装基准

`source.frames` 描述相对某刚体固定的无质量基准。工具基准必须区分安装接口与实际工作点 TCP；相机机械安装基准与光学基准分别命名。采用光学约定时，X 向右、Y 向下、Z 向前。IMU 基准按实际测量轴定义，并记录其与安装基准的关系。

基准仍由 CAD 命名坐标系派生，不能在 YAML 中重复 XYZ/RPY。v1 仅输出这些静态基准，不包含传感器模型、标定结果、驱动或执行器配置。

### 5.5 腕部及其他多轴机构的专项核对

对左右腕和其他紧邻多轴机构，必须逐轴保留以下评审记录；按实际设计列出关节，不预设轴数或排列顺序：

- 从近端到末端列出父子刚体和真实连接顺序，确认中间运动刚体没有被合并、遗漏或调换。
- 记录各轴相交、平行或异面的关系，原点选取依据及设计偏置；用受控尺寸核对轴间距离。
- 固定其他关节，每次只使一个关节由零位沿正向运动，记录末端位置和朝向变化；核对右手定则与关节功能。
- 左右分别核对，不从镜像外观推断相同的符号、零位或限位。已镜像的坐标系仍须保持右手。
- 记录工作范围两端的姿态、止挡、间隙和线缆条件；确认范围对应声明的零位和正方向。
- 接口基准、TCP 或末端安装面必须随正确的末端刚体运动；不能以整机外观接近替代该项确认。

这些记录用于机械评审及导出后的逐关节可视化核对；当前自动圆柱轴线检查不能代替它们。

## 6. 关节、轴线与限位

### 6.1 关节类型和连接关系

| `type` | 机械含义 | 需要提供的参数 |
|---|---|---|
| `fixed` | 父、子刚体之间没有相对运动 | 父子关系及 CAD 基准；不得填写轴、限位、轴线引用或限位证据 |
| `revolute` | 有位置边界的转动 | 正轴、原生轴线引用、角度上下限、速度、力矩、证据 |
| `continuous` | 没有位置边界的转动 | 正轴、原生轴线引用、速度、力矩、证据；不得填写位置上下限 |
| `prismatic` | 直线运动 | 正轴、原生轴线引用、行程上下限、速度、推力、证据 |

`parent` 和 `child` 引用刚体 `name`，不能引用其 `id` 或 CAD 文件名。可动关节的 `child` 是按正运动定义相对父刚体运动的一侧。关节数量、类型、名称和连接关系必须与受控机械关节清单逐项一致。

带线缆、软管或机械止挡的转轴，不能只因外观可整圈转动就声明为 `continuous`。被动自由度也应记录真实类型；不得伪装为固定连接。v1 对所有可动关节要求可信的 `effort` 和 `velocity`，无法提供时应先确认参数责任和合同适用性，不能填默认大数。

### 6.2 正方向和原生轴线引用

`axis` 是子刚体关节坐标系中的有符号单位向量。转动正方向按该向量的右手定则定义；直线正方向沿该向量。分量必须有限，向量长度与 1 的误差不超过 `1e-9`；不能靠系统猜测、归一化或自动翻转来确定符号。

`axis_reference` 提供从 CAD 独立读取运动轴线的对象，必须指向该关节实际机械接口，不能借用远处恰好平行的圆柱。

| 字段 | 定义 |
|---|---|
| `component` | 精确零件实例路径，与原生采集身份一致 |
| `feature_name` | 建议使用的稳定特征名；该特征必须唯一解析到一个圆柱面 |
| `face_index` | 不使用命名特征时，原生读取序列中从 0 开始的面序号；不是界面显示编号，也不是持久身份。同一文件在重新打开或采集时面序可能改变，必须重新确认实际指向的面 |
| `body_type` | `solid` 或 `sheet`，默认 `solid`；必须与实际选择的实体类型一致 |
| `note` | 可选的选择和机械意义说明，不能替代实际几何引用 |

至少提供 `feature_name` 或 `face_index`。优先使用稳定命名特征，并在结构变更后复核其机械含义。建议每次只选一种定位方式；同时填写时，原生采集优先使用 `feature_name`，不会因其失败改用 `face_index`。特征解析到多个圆柱面时返回 `cad_axis_reference_ambiguous`，没有有效圆柱面时返回 `cad_axis_reference_not_cylinder`，不会自动猜选。原生记录须证明所选面是圆柱、轴向单位化且半径为正。

仅有正确的 `face_index` 格式不能证明引用稳定。使用面序号的交付须在本次采集记录中复核真实几何；静态检查无法完成这一步，跨会话失配应修正引用，不能放宽轴线门禁。

圆柱参数方向是无向轴线证据，不能证明控制正方向。正方向必须结合零位、正向姿态和机械评审确认。v1 的直线关节同样需要支持的圆柱轴线引用；无法提供时应扩展取证接口，不能虚构引用或在 CAD 中加入影响质量的假几何。

### 6.3 参数的物理含义

| 字段 | 定义与要求 |
|---|---|
| `lower`、`upper` | 相对声明零位的允许位置范围，必须有限且 `lower < upper`；转动单位 rad，直线单位 m |
| `velocity` | 关节输出侧允许速度，必须有限且大于零；不能直接使用未换算的电机 rpm |
| `effort` | 关节输出侧允许力矩或推力，必须有限且大于零；不能直接使用电流或未换算的电机轴参数 |
| `limit_evidence` | 本关节参数对应的包内文件、文件摘要、文本锚点和可选说明 |

`limit_evidence` 位于关节层，与 `limits` 同级；`limits` 只包含 `lower`、`upper`、`effort`、`velocity`，不得添加 `limits.evidence`。

证据应分别记录机械硬限位、允许工作范围和必要安全余量。URDF 中填写经过确认的工作范围，不能把 CAD 配合限位、硬止挡位置和控制允许范围混为一谈。

速度与力矩或推力必须说明持续或峰值条件、减速比、效率、温度或工作制等适用条件。仅有机械止挡图不能证明驱动能力；涉及电机、减速器或控制限制的数值须由对应参数责任人确认。

若正方向或零位发生改变，应重新核对整个位置区间及下游接口，不能只修改一个 `axis` 符号。

## 7. 材料、质量、质心与惯量

### 7.1 材料模式必须显式选择

`source.material_source` 只能是 `cad` 或 `documented_table`，不得在实例之间隐式混用两种来源。

`cad` 模式下提供非空 `documented_masses` 会被拒绝，不会与 CAD 质量合并。采用质量表时，全部纳入实例都必须覆盖，不允许只覆盖缺材料的个别零件。

| 模式 | 结构组必须提供的依据 | 处理方式 |
|---|---|---|
| `cad` | 每个纳入实体的实际物理材料；评审记录保留材料名称、数据库来源和适用配置 | 核实原生材料赋值并使用 CAD 质量属性；数据库来源的设计正确性由人工评审 |
| `documented_table` | 所有纳入零件实例的质量、采用原因及完整证据表 | 用声明质量缩放对应 CAD 惯量，并保留均匀密度假设 |

物理材料不等于颜色、纹理或外观。默认密度、能算出正质量或总量看起来合理，都不能替代明确材料赋值。多实体零件须确认每个纳入实体的有效材料，避免实体级赋值与零件级赋值相互覆盖。

### 7.2 质量与配置边界

质量表必须说明包括哪些附件、紧固件、电机、电池、线束和负载，排除哪些对象，以及适用的装配配置。不得重复计入总成与其内部零件，也不得把整个机器人实测质量分配给一个零件来满足总量检查。

规格或实测依据应记录对象型号与版本、测量或引用方法、原单位、日期及适用条件。实测时说明仪器、精度和样品状态。用于输入的质量必须对应精确装配实例；同一零件的多个实例仍需完整覆盖。

### 7.3 原生覆盖值与惯量假设

当前 v1 不接受零件、实例或装配中的有效质量、质心或惯量覆盖。两种材料模式都必须清理这些覆盖；需要规格或实测质量时通过 `documented_table` 声明，不用 SolidWorks 覆盖值绕过来源记录。

系统从原始读数派生各刚体质量、质心和完整惯量张量，记录参考点、表达坐标系、SI 单位及惯性积约定。结构组不手工抄写惯量，不删除非对角项，也不通过调节张量让报告变绿。

规格质量缩放保留 CAD 的质量分布假设，不能证明复杂设备的真实内部质心和惯量。空壳电机、电池或控制器简模尤其需要记录该假设。实测质心、实测惯量和动态准确性需要独立合同及验收，v1 不因质量表完整就授予这些能力。

## 8. 证据、几何与独立验收范围

### 8.1 证据必须能对应对象和参数

每项依据应能回答：哪个对象、哪个结构版本、哪个参数、原始单位、取值条件、来源位置和确认人。截图和 PDF 可以作为原件，但锚点必须位于含对象标识及参数说明的 UTF-8 文本或 Markdown，可带 UTF-8 BOM，并引用原件的具体页码、表格或测量记录。当前读取器不严格拒绝其他编码；偶然匹配到锚点不代表编码合格，非 UTF-8 中文也不能保证正确匹配。

一般证据绑定采用以下字段：

| 字段 | 要求 |
|---|---|
| `file` | 包内相对路径，文件真实存在并被归档 |
| `sha256` | 与该文件完整字节一致的 64 位小写十六进制摘要；由工具计算或核实 |
| `anchor` | 文件中存在的对象或记录标识，能明确定位本项依据；按区分大小写的原文子串匹配，不支持正则、通配符或自动规范化 |
| `note` | 可选补充说明，例如页码、单位换算或适用条件 |

限位记录示例：

```text
对象：shoulder_joint
结构版本：arm/r1
零位与正方向：引用 mechanical-review.md 中该关节的姿态记录
工作范围：lower=-1.2 rad，upper=1.2 rad
硬限位与安全余量：引用受控图纸的止挡尺寸与计算记录
输出速度上限：2 rad/s；注明规格来源、减速换算和适用条件
输出力矩上限：8 N·m；注明持续或峰值及对应工作制
确认：参数责任人与机械评审记录
```

文本中出现锚点只证明文件可定位，不证明参数正确。不得用包含关节名称但没有参数依据的文件充当合格证据，也不得用旧版本证据覆盖已变更的接口。

### 8.2 质量表绑定

`source.mass_evidence` 使用 `reference`、`file`、`sha256` 和可选 `note`；每个 `documented_masses` 项使用 `mass_kg`、`reason`、`evidence`。此处的 `evidence` 是共享质量文件中的文本锚点，字段名不是 `anchor`。

```yaml
material_source: documented_table
mass_evidence:
  reference: arm r1 零件质量依据
  file: evidence/masses.txt
  sha256: REPLACE_WITH_FILE_SHA256
  note: 原规格及测量附件见 evidence/drawings/
documented_masses:
  base-1:
    mass_kg: 0.8
    reason: 采用对应版本的质量测量记录
    evidence: base_mass_r1
  arm-1:
    mass_kg: 0.3
    reason: 采用对应版本的供应商规格
    evidence: arm_mass_r1
```

该片段替换 `source.material_source` 并补入 `source`，不要建立第二个 YAML 文件。质量文件必须包含两个锚点及各自完整依据；所有其他纳入实例也必须有对应项。

### 8.3 几何与例外

用于交付的 CAD 应保留真实运动轴、安装面、连接接口、关键尺寸和质量归属。简化孔、外观或内部零件时，记录简化内容、影响和适用用途。视觉、碰撞与质量几何的用途应分别说明，不能把视觉简模直接当作动态或接触模型。

v1 导出原生 STL 视觉几何并保持 SI 单位和单位缩放。每个纳入实例都须有非空、可解析的几何，不能通过手修网格、偏移模型或删除异常零件修复质量问题。

薄片等合法近零体积几何可在 `checks.documented_exclusions` 中绑定精确实例、原因与证据。该声明仅用于相应几何检查，不删除实例，不免除质量、归属、轴线或其他必检要求。

```yaml
documented_exclusions:
  - component: cover-1
    reason: 受控图纸声明的薄片视觉几何
    evidence:
      file: evidence/geometry-exceptions.txt
      sha256: REPLACE_WITH_FILE_SHA256
      anchor: cover_sheet_r1
```

该片段属于 `checks`，只能引用实际纳入并归属某刚体的实例。缺失证据、空网格和错误坐标变换不能据此豁免。

结构评审还应按用途检查零位、工作姿态和限位姿态的干涉、间隙、线缆或软管运动。v1 不执行全行程碰撞验证，不生成碰撞简化模型，也不证明动力学、训练或实机控制可用。

### 8.4 独立质量与尺寸范围

| 字段 | 定义 |
|---|---|
| `checks.expected_mass_kg` | 当前配置下全部纳入实例的预期总质量区间 `[下界, 上界]`，单位 kg |
| `checks.expected_extent_m` | CAD 零位下、按总装坐标系计算的轴对齐整机包围盒三个尺寸中最大值的预期区间 `[下界, 上界]`，单位 m；不是 XYZ 三维向量 |

两项均必填，数值有限且正，区间满足下界不大于上界。范围应来自独立质量预算、尺寸图或实测及其合理不确定度，不能抄回本次导出结果，再放宽区间使其通过。

数字模型的一致性容差与加工、装配公差不同。当前坐标位置和轴线偏移检查为 0.05 mm，角度检查为 0.05°；这些值不代表实物制造精度。机械公差依据受控图纸，完整数值验收合同见[质量规范](quality.md#numerical-contract)。

## 9. `robot.yaml` 完整定义

### 9.1 基础示例

下例演示两刚体、一个转动关节。实例、CAD 名称、参数、范围和证据必须替换为实际设计；示例数值不是默认值，摘要占位符不能用于正式交付。

```yaml
schema_version: solidworks-to-urdf.input/v1
hardware_id: arm
source:
  provider: solidworks
  robot_name: arm
  assembly: cad/robot.SLDASM
  configuration: Default
  material_source: cad
  bodies:
    - id: base
      name: base_link
      components: [base-1]
      frame:
        coordinate_system: CS_base
    - id: arm
      name: arm_link
      components: [arm-1]
      frame:
        coordinate_system: CS_arm
  joints:
    - id: shoulder
      name: shoulder_joint
      type: revolute
      parent: base_link
      child: arm_link
      axis: [0, 0, 1]
      axis_reference:
        component: arm-1
        feature_name: shoulder_shaft
        body_type: solid
      limits:
        lower: -1.2
        upper: 1.2
        effort: 8
        velocity: 2
      limit_evidence:
        file: evidence/limits.txt
        sha256: REPLACE_WITH_FILE_SHA256
        anchor: shoulder_joint
checks:
  expected_mass_kg: [1.0, 1.2]
  expected_extent_m: [0.3, 0.4]
```

可在 `source` 下增加附加 CAD 基准：

```yaml
frames:
  - id: tool
    name: tool_frame
    parent: arm_link
    coordinate_system: CS_tool
```

### 9.2 字段清单

| 字段 | 必填条件与定义 |
|---|---|
| `schema_version` | 必填，固定为 `solidworks-to-urdf.input/v1` |
| `hardware_id` | 必填，硬件标识；与 CAD 版本清单一致 |
| `source` | 必填，以下机械来源定义 |
| `checks` | 必填，独立质量、尺寸范围及可选几何例外 |
| `source.provider` | 必填，固定为 `solidworks` |
| `source.robot_name` | 必填，模型名称；建议与硬件标识一致，URDF 机器人身份使用 `hardware_id` |
| `source.assembly` | 必填，包内总装相对路径 |
| `source.configuration` | 必填，准确配置名 |
| `source.material_source` | 必填，`cad` 或 `documented_table` |
| `source.bodies` | 必填，非空刚体列表 |
| `source.joints` | 必填，关节列表；单刚体用空列表 |
| `source.frames` | 可选，无质量的附加 CAD 基准列表 |
| `source.documented_masses` | `documented_table` 时必填；`cad` 模式不得填写非空表 |
| `source.mass_evidence` | 使用质量表时必填，共享质量证据绑定 |
| `bodies[].id`、`name` | 必填，各自在刚体集合中唯一，身份及命名见第 3 节 |
| `bodies[].components` | 必填，非空精确实例列表，归属见第 4 节 |
| `bodies[].frame.coordinate_system` | 必填，绑定一个实际 CAD 基准；不得另填 `xyz` 或 `rpy` |
| `joints[].id`、`name` | 必填，各自在关节集合中唯一 |
| `joints[].type`、`parent`、`child` | 必填，类型和连接关系见第 6 节 |
| `joints[].axis`、`axis_reference` | 可动关节必填，固定关节禁止填写 |
| `joints[].limits`、`limit_evidence` | 可动关节必填，固定关节禁止填写；内部字段见第 6、8 节 |
| `frames[].id` | 交付时显式填写稳定身份；当前解析器允许省略并以 `name` 代入，该要求须由人工评审核对 |
| `frames[].name`、`parent`、`coordinate_system` | 提供附加基准时必填，父对象为刚体名称；禁止填写 `xyz` 或 `rpy` |
| `checks.expected_mass_kg`、`expected_extent_m` | 必填，定义见第 8.4 节 |
| `checks.documented_exclusions` | 可选，仅限有证据的实际几何例外，定义见第 8.3 节 |

附加基准不得与刚体重名；其生成的 `<name>_fixed` 关节不得与已有关节重名。上述以外的字段不属于 v1 合同，不能把机器人机械定义、历史配置格式和平台部署参数混写。

尤其不能增加手填 `coordinate_systems` 列表、`allowed_roots`、`worker_url`、`job_id`、执行器或传感器配置。坐标系清单由实际引用派生，执行环境由平台配置。

## 10. 评审记录与交付清单

### 10.1 评审记录

`evidence/mechanical-review.md` 是人工评审记录的约定位置，不是新的机器解析合同。可以引用现有受控评审记录，但交付包必须保留相应依据，不能只留一个不可访问的外部链接。

评审记录按下列结构逐项填写。表中每行对应一个实际对象；可以引用受控附件，不能以“沿用旧版”省略已变化的定义。

```markdown
# Mechanical review

## 交付身份
硬件、结构版本、父版本、总装路径、指定配置、受控来源引用、评审日期。
结构负责人、参数责任人、机械评审人。

## 本次变更
变更原因；受影响的零件、接口、关节、基准、限位和质量。
改名、拆分、合并、左右交换及下游兼容影响。

## 实例与刚体
| 实例路径 Name2 | 引用文件与配置 | 刚体 id / name | 刚性连接依据 | 纳入或抑制说明 |
|---|---|---|---|---|

## 几何基准
| CAD 坐标系 | 所属对象 | 原点三维定位依据 | X / Y / Z 正向依据 | 受控图纸或尺寸 |
|---|---|---|---|---|

## 关节与姿态
| 关节 id / name | 类型 | 父 / 子刚体 | 原生轴线特征 | 子基准中的正轴 | 零位与正运动附件 |
|---|---|---|---|---|---|
各可动关节补充：工作范围两端姿态、硬限位、安全余量、输出侧速度和力矩或推力及来源。
多轴机构补充：真实连接顺序、轴间尺寸、左右差异、末端随动及线缆条件。

## 物理属性与独立范围
材料或质量表来源、覆盖值清理结果、纳入附件与负载、质量分布假设。
整机质量预算与尺寸范围的独立来源、原单位、换算和不确定度。

## 附加基准、简化与例外
安装接口、TCP、传感器轴约定；几何简化及用途；例外原因和证据。

## 评审结论
| 检查项 | 依据与结果 | 确认人 / 日期 | 未决问题及处置 |
|---|---|---|---|
明确通过或退回；列出本次允许用途及仍需另行验收的用途。
```

零位、正运动及范围端点记录须能定位到具体关节、结构版本和姿态值；使用图片时同时记录观察方向，防止左右或旋转符号歧义。必需定义未确认时结论为退回，不得以空白签核或“待后续补充”交付。

### 10.2 交付清单

| 交付检查 | 合格要求 |
|---|---|
| 版本 | `hardware_id`、`revision` 及配置与本次评审一致，硬件标识与 `robot.yaml` 一致；原件可重新取得；版本链明确；CAD 清单未被覆盖 |
| 装配 | 指定配置已强制重建并保存；总装和完整依赖可从交付目录重新打开 |
| 命名与身份 | 左右和功能名称明确；旧对象延续身份；实例不按文件名混淆 |
| 刚体 | 每个纳入实例归属一次；分组符合真实刚性连接 |
| 运动关系 | 关节名称、数量、类型及父子关系与机械清单一致 |
| 坐标系 | 每个刚体独立基准；原点三维定位明确；三轴右手且符合规定方向 |
| 零位与正方向 | 保存姿态有依据；逐关节正运动可核对；偏置及左右差异已说明 |
| 限位与能力 | 工作范围、硬限位和安全余量明确；速度与力矩或推力有适用依据 |
| 物理属性 | 有效材料或完整质量表；零件、实例和总装均无有效质量、质心或惯量覆盖，原生采集再次核实；惯量假设已说明 |
| 几何与安装 | 关键轴、面和尺寸完整；简化、间隙及适用运动姿态已评审 |
| 证据 | 文件与版本对应；参数、单位、锚点和附件可定位；摘要真实 |
| 独立范围 | 质量预算和整机尺寸范围有独立来源 |
| 未决事项 | 所有必需定义均已确认；影响当前用途的未知项没有被当作通过 |

评审通过后封存 CAD 版本并提交输入目录。封存工具及静态自检的操作见[操作手册第一节](operations.md#1-prepare-the-mechanical-handoff)。缺少必需字段、原生引用或参数依据时，先补齐输入，不修改产物或放宽检查。

## 11. 验收与实现边界

当前工具能力与本规范的机械交付要求按下表区分。人工评审结论不得被一个自动“通过”标志替代。

| 要求 | v1 自动检查 | 必须保留的机械评审 |
|---|---|---|
| 命名与身份 | 字符格式、重复名称、实体集合和根节点 | 左右、功能、编号、后缀、接口兼容和附加基准显式稳定身份；连续或末尾下划线尚无单独门禁 |
| 输入版本 | 入队核验封存 CAD 清单与摘要；采集时重新检查输入合同并绑定文件 | 受控来源实际可取、结构版本链；排队期间保持完整输入不变 |
| 文件与编码 | 包内相对路径、越界、链接、大小写冲突、保留名称等已实现路径约束 | 完整 Windows 命名规则和 SolidWorks 可打开的路径长度；`< > " \| ? *` 尚无 Linux 静态门禁；UTF-8 证据编码由人工确认 |
| 刚体与装配 | 依赖闭合、配置一致、实例唯一归属、树结构、采集重建成功 | 实际刚性连接、预期自由度、配合完整性和选定配置的设计正确性 |
| 坐标系 | 有限正交右手矩阵、引用存在、CAD 与模型和 URDF 位姿一致 | 基准物理含义、规定轴向、所属对象及每刚体独立基准；当前未强制一对一绑定 |
| 关节原点与轴 | 原点到原生圆柱轴线的距离、轴线共线性、输入与导出符号一致 | 沿轴定位、所选特征是否为真实接口、机械正方向及零位偏置 |
| 限位 | 范围有序、参数有限且正、证据文件摘要和文本锚点绑定 | 证据实际含义、硬限位与工作范围、输出侧能力及适用条件 |
| 物理属性 | 材料或质量表覆盖、原生覆盖检查、完整惯量与装配闭合、基本物理合理性 | 材料与实物一致、测量依据、质量归属和分布假设 |
| 几何与加载 | 网格覆盖、单位、文件完整性、零位放置及 MuJoCo 加载 | 全行程干涉、间隙、接触、动态行为和其他消费者的适用性 |
| 评审与发布 | 验证报告重算、输入和产物字节绑定、候选 PR 提交 | 机械评审记录内容；v1 尚未自动验证逐项签核，候选 PR 不等于模型正式发布 |

自动数值校验通过、机械定义评审通过和具体用途验收是不同结论。v1 的通过报告证明所列 URDF 及证据检查；仿真、训练、实机控制还需要对应的碰撞、驱动、接触、标定和动态验收。现有自动门禁与报告规则见[质量规范](quality.md)，模型评审与发布步骤见[操作手册](operations.md#5-review-and-release-the-model)。

统一路径入口还将绑定完整目录摘要并在排队、采集前复核；该能力不属于已发布的 v1.0.0，状态见[部署说明](deployment.md#release-and-deployment-status)。

## 12. 常见不合格输入

| 问题 | 正确处理 |
|---|---|
| 只提交总装，引用仍指向个人工程目录 | 收集完整依赖，在交付目录重开并确认引用 |
| 仅给一条轴线，未定义原点沿轴位置 | 增加受控点或平面等定位依据，并据此建立 CAD 基准 |
| 右手系成立，但根坐标前向或左右错误 | 按机型方向基准重新建立坐标系，逐轴评审 |
| 左右腕外观正确，但正转定义相反 | 分别记录正运动姿态，核对轴符号、零位与限位区间 |
| 多个可动刚体复用一个坐标系 | 为每个刚体建立独立、明确命名的机械基准 |
| 整个电机或减速器子装配被并为刚体 | 按真实定子、转子及输出连接拆分实例归属 |
| 密度默认、质量覆盖或总量看似正确 | 补全有效材料或完整声明质量证据，清理未支持的覆盖 |
| 限位、速度或力矩使用“足够大”的默认值 | 取得实际参数依据，由责任人确认适用条件 |
| 扩大质量或尺寸区间以迁就导出结果 | 回查配置、遗漏、单位、材料和独立预算 |
| 改动 CAD 后继续沿用原结构版本 | 新建交付目录和版本，保留上一版及变更记录 |
| 手改 URDF 原点、轴或惯量后重新提交 | 修正 CAD 基准、机械定义或生成规则，再完整重建 |
