# SolidWorks 结构工程与交付规范

本规范规定 SolidWorks 结构工程的交付要求，涵盖身份与命名、文件与版本、装配与运动、基准、规格及物理属性。

**结构组只交付 SolidWorks 原生工程。** 主装配、零件及其依赖必须完整、已保存且可重新打开。流水线负责生成机器人定义、版本清单、采集证据、URDF、网格、验收报告和 PR；结构组不编写流水线 YAML、版本清单、姿态文件或重复报告，也不手工导出模型。

工程事实优先由装配、配合、配置、参考几何体和有效材料表达；无法直接表达的含义，使用统一 CAD 模板中的原生工程属性或引用已有受控记录。工程属性只补充必要事实和受控引用，不另建刚体／关节映射表或完整机器人配置。

本文中的“应”“须”“必须”表示必需项，“建议”表示推荐项。要求适用于所有纳入模型的零件、实例、关节和机构。工程问题在原生设计中修正；缺失、冲突或含义不明的事实不能由流水线猜测补齐。

## 1. 交付范围与工程身份

### 1.1 交付范围

交付范围必须明确整机、模块、附件和负载的边界，以及对应的装配配置。电机、减速器、电池、紧固件、线束和附加设备是否纳入几何与质量，应与本版本的设计用途一致。

结构组负责装配关系、运动约束、机械基准、材料、限位和零部件身份。驱动与实测参数由相应参数责任人确认，通过原生工程属性或受控零部件记录关联；结构组不承担无依据的参数推算。

结构负责人是结构组内负责本次交付版本并完成工程确认的人。平台负责维护 CAD 模板、参数关联规则及流水线。

### 1.2 工程身份

主装配的原生工程属性或关联 PDM 记录必须明确以下信息。工程属性的字段、命名和单位由统一 CAD 模板约定。模板由平台维护并版本化；工程记录绑定所用模板版本，模板更新按受控变更处理。

| 信息 | 要求 |
|---|---|
| 产品／硬件标识 | 稳定对应实际产品，不随目录或文件改名而变化；使用 1–64 个 ASCII 字符，以字母开头，其余为字母、数字、`_`、`.` 或 `-` |
| 结构版本 | 唯一标识本次设计状态，对应可重新取得的原件 |
| 主装配 | 本次交付唯一的入口装配；其他装配属于其依赖 |
| 交付配置 | 准确指向已保存的配置，明确其参考姿态和适用范围 |
| 变更关系 | 可追溯上一版本；首次交付明确为初版 |
| 责任与审批 | 沿用工程属性或 PDM 中的负责人、变更及审批记录 |

文件名、修改时间和“最新”“最终版”等字样不能代替工程身份。显示状态、活动窗口和当前桌面姿态不能代替交付配置。

### 1.3 原生工程属性

统一使用 `dp` 命名空间，字段契约为 `native-discovery/v1`。在主装配的自定义属性中维护以下信息；配置专属值须对应交付配置，不得与文档级定义冲突。填写工程事实和受控引用，不填写流水线运行参数。

| 属性 | 要求 |
|---|---|
| `dp.hardware_id` | 第 1.2 节的稳定硬件标识，须已配置对应模型仓库 |
| `dp.revision` | 本次结构版本 |
| `dp.parent_revision` | 上一结构版本；初版留空 |
| `dp.owner` | 本版本结构负责人 |
| `dp.change_summary` | 本版本工程变更摘要；初版说明交付范围 |
| `dp.control.system` | 原件版本管理方式：`git`、`pdm` 或 `handoff` |
| `dp.control.reference` | 可重新取得本版本原件的受控记录标识 |
| `dp.delivery_configuration` | 已保存的交付配置名称 |
| `dp.robot_name` | 整机模型名称，采用第 2.3 节的 snake_case 规则；省略时由硬件标识派生，不影响刚体、关节或接口名 |
| `dp.design_budget_record` | 独立整机质量与外形预算记录的固定引用 |

关节属性写在主装配中，`<关节名>` 与配合组的名称完全一致：

| 属性 | 要求 |
|---|---|
| `dp.joint.<关节名>.axis_sign` | `1` 或 `-1`，将原生采集轴向绑定到经工程确认的正运动方向 |
| `dp.joint.<关节名>.type` | 仅在需要明确连续运动时填 `continuous`；不得覆盖配合所确定的自由度 |
| `dp.joint.<关节名>.limits_record` | 无可采用的原生限位时，引用允许工作范围；与原生限位并存时必须一致 |
| `dp.joint.<关节名>.drive_record` | 经参数责任人确认的关节输出侧能力记录 |

受控引用采用 `<相对文件路径>#<记录键>`，例如 `joints/arm.json#shoulder_drive`。记录由平台规格库或参数责任人维护，结构组关联已确认的版本。平台保证记录可取得、无同名歧义，并在运行时留存原文、记录键和文件摘要。

允许范围记录包含 SI 单位的 `lower`、`upper`；驱动记录包含正数 `effort`、`velocity`；整机预算包含 `expected_mass_kg` 和 `expected_extent_m` 两个递增正数区间，后者表示整机最大外形尺寸。各字段的机械含义、来源及适用条件分别遵循第 8、9、10 节；原生配合的单位由采集适配器统一转换。

无法从主装配唯一识别刚体基准时，可在相应组件文档中用 `dp.body_datum` 引用本实例所属刚体的 `CS_<刚体名>`。重复实例必须仍能按实际装配上下文唯一解析，不能借用共享文档属性将不同安装位置合并为一个刚体。

## 2. 命名与原生引用

### 2.1 名称与身份

**交付前必须确定全部零部件、实例、刚体、关节和接口的名称。** 文件名、物料号、安装实例和模型接口各有用途，不能互相替代。新工程及已有型号的新增接口采用本节规则；已有受控名称按第 2.5 节冻结或受控迁移。本节规定交付要求，自动覆盖范围见第 11.1 节。

| 对象 | 名称／身份要求 | 原生载体与示例 |
|---|---|---|
| 零件、子装配文档 | 物料号识别可复用的工程件；名称说明功能；修订单独记录 | 文档／配置属性或 PDM：物料号 `RA-ARM-0123`，名称“输出轴”，修订 `B02` |
| 装配实例 | 标识本次安装位置和功能；同一工程件安装多次，实例分别识别 | 所属装配中的实例名或组件参考：`left_arm`、`right_arm`；部件 `output_shaft_01` |
| 刚体 | 标识一个真实刚性集合，成员由第 5 节的连接确定 | 原生基准承载接口名，如 `left_upper_arm_link`，不按基准名推断成员 |
| 关节 | 标识一处相对运动关系；一组配合共同实现一个关节，不按配合条数命名 | 对应关节基准及配合组：`left_elbow_pitch_joint` |
| 工具、传感器、安装接口 | 安装基准与工作／测量基准分别命名，归属明确 | `left_gripper_mount`、`left_gripper_tcp`、`front_camera_optical` |
| 配置 | 名称说明用途并稳定指向已保存状态，不用“当前配置”作为身份 | 原生配置：`delivery_zero`、`delivery_reference`；只指定一个交付配置 |

文件名和工程显示名可用中文，建议采用 `<物料号>_<功能名>.SLDPRT` 或 `.SLDASM`；已有受控编号沿用原体系。同一工程件不因重复安装或安装侧改变而换物料号。左右制造件不同、镜像导致实际几何不同或其他制造差异需要区分时，按物料管理规则分配不同物料号，不能仅靠“左件／右件”显示名区分。

实例以完整装配上下文定位，例如 `left_arm/output_shaft_01` 与 `right_arm/output_shaft_01`。实例标识在所属装配内唯一，完整路径在本模型内唯一；引用文档及配置同时保留。SolidWorks 自动附加的实例序号可保留在原生路径中，但不能代替左右、安装位置和机械功能。

统一 CAD 模板须明确采用实例名或组件参考中的一种作为受控标识，不混用。文档属性不能单独承载同一文件多个安装实例的身份。流水线须保留实际原生路径，并将受控标识绑定到该实例，不按文件名合并重复件。

### 2.2 身体部位与部件用词

身体部位与部件统一使用下表的英文词根，中文用于工程说明。上肢、下肢表示模块范围；身体部件表示真实结构；关节区域表示运动发生的位置。三者不互相替代。

| 类别 | 中文名称 | 规范词根 | 含义与使用边界 |
|---|---|---|---|
| 中心结构 | 躯干 | `torso` | 主躯干；不与 `trunk` 混用 |
| 中心结构 | 胸部 | `chest` | 明确位于胸部的独立结构；不作为整个躯干的别名 |
| 中心结构 | 骨盆 | `pelvis` | 骨盆刚性结构；不与腰部关节名 `waist` 混用 |
| 中心结构 | 头部 | `head` | 头部结构；头部转动的关节区域称 `neck` |
| 模块 | 上肢／手臂 | `arm` | 整条上肢模块，不代替其中的上臂或前臂 |
| 模块 | 下肢／腿 | `leg` | 整条下肢模块，不代替其中的大腿或小腿 |
| 上肢部件 | 上臂 | `upper_arm` | 肩至肘的结构；不使用 `humerus` 代替 |
| 上肢部件 | 前臂 | `forearm` | 肘至腕的结构；不与 `lower_arm`、`radius` 混用 |
| 上肢部件 | 手 | `hand` | 手部结构；不代替腕部关节名 `wrist` |
| 上肢部件 | 手掌 | `palm` | 独立手掌结构，与整手模块区分 |
| 上肢部件 | 拇指、食指、中指、无名指、小指 | `thumb`、`index_finger`、`middle_finger`、`ring_finger`、`little_finger` | 手指按实际结构命名，指节用 `proximal`、`middle`、`distal` 区分近、中、远端 |
| 下肢部件 | 大腿 | `thigh` | 髋至膝的结构；不与 `hip`、`femur` 混用 |
| 下肢部件 | 小腿 | `shank` | 膝至踝的结构；不与 `calf`、`lower_leg`、`tibia` 混用 |
| 下肢部件 | 足 | `foot` | 足部结构；不以 `ankle` 命名整个足 |
| 下肢接口 | 足底 | `sole` | 足底接触或参考基准，不默认新增一个物理刚体 |
| 移动机构 | 底盘、车轮、脚轮 | `chassis`、`wheel`、`caster` | 用于实际存在的轮式或轮足结构，底盘不作为躯干的别名 |
| 关节区域 | 颈、腰 | `neck`、`waist` | 连接头与躯干、躯干与骨盆的机构区域 |
| 关节区域 | 肩、肘、腕 | `shoulder`、`elbow`、`wrist` | 上肢运动区域，不代替相邻上臂、前臂或手 |
| 关节区域 | 髋、膝、踝 | `hip`、`knee`、`ankle` | 下肢运动区域，不代替相邻大腿、小腿或足 |
| 末端设备 | 夹爪、工具法兰、工具 | `gripper`、`tool_flange`、`tool` | 按实际设备和连接边界区分；夹爪不一律称为手 |

安装位置使用完整的 `left`／`right`、`front`／`rear`、`upper`／`lower`，左右以机器人自身视角定义。`l_`、`r_` 仅用于采用 REP 既定名称的互操作基准，不能用于新建的身体刚体或运动关节。

一般机械部件使用实际功能词，例如壳体 `housing`、支架 `bracket`、输出轴 `output_shaft`、法兰 `flange`、轴承 `bearing`、电机 `motor`、减速器 `reducer`、紧固件 `fastener`。其他机构在首版确认准确词根后沿用，不强行套用人体名称，也不由流水线自动翻译。

### 2.3 刚体与关节名称

模型接口名（即导出名称）采用小写 ASCII snake_case，匹配 `^[a-z][a-z0-9_]*$`。刚体用 `<位置或模块>_<物理部件>_link`，物理部件词根见第 2.2 节；运动关节用 `<位置或模块>_<关节区域>_<运动功能>_joint`，中心结构省略左右。真实重复模块可增加固定标识，如 `left_arm_02_elbow_pitch_joint`，不能用电机地址、控制通道、策略索引或特征顺序代替机械语义。

根刚体名固定为 `base_link`，物理归属及定位由本型号设计按第 7.1 节明确。其他刚体按真实刚性集合命名，如 `pelvis_link`、`left_upper_arm_link`、`left_forearm_link`、`left_thigh_link`、`left_shank_link`、`left_foot_link`；命名不改变根、刚体边界或真实连接。

没有独立身体部位名称的中间运动件，可按机构功能命名，如 `left_shoulder_pitch_link`、`left_hip_yaw_link`；仍须有独立、真实的刚体归属。关节名不必与子刚体同名，例如 `left_elbow_pitch_joint` 的子刚体可以是 `left_forearm_link`。词表不规定运动链顺序。

同一模型的刚体、关节和附加基准分别唯一；刚体与附加基准不得重名，附加基准生成的固定连接名不得与关节重名。名称不能只靠大小写区分；冲突回到原生设计中明确，不靠追加数字、删除标点或拼音猜译修补。

常见机器人关节采用下表的完整名称，仅使用实际存在的自由度；表格不规定关节数量或连接顺序。

| 关节功能 | 名称 |
|---|---|
| 颈部俯仰、滚转、偏航 | `neck_pitch_joint`、`neck_roll_joint`、`neck_yaw_joint` |
| 腰部俯仰、滚转、偏航 | `waist_pitch_joint`、`waist_roll_joint`、`waist_yaw_joint` |
| 肩部俯仰 | `left_shoulder_pitch_joint`、`right_shoulder_pitch_joint` |
| 肩部滚转 | `left_shoulder_roll_joint`、`right_shoulder_roll_joint` |
| 肩部偏航 | `left_shoulder_yaw_joint`、`right_shoulder_yaw_joint` |
| 肘部俯仰（屈伸） | `left_elbow_pitch_joint`、`right_elbow_pitch_joint` |
| 腕部俯仰 | `left_wrist_pitch_joint`、`right_wrist_pitch_joint` |
| 腕部偏航 | `left_wrist_yaw_joint`、`right_wrist_yaw_joint` |
| 腕部滚转 | `left_wrist_roll_joint`、`right_wrist_roll_joint` |
| 髋部俯仰 | `left_hip_pitch_joint`、`right_hip_pitch_joint` |
| 髋部滚转 | `left_hip_roll_joint`、`right_hip_roll_joint` |
| 髋部偏航 | `left_hip_yaw_joint`、`right_hip_yaw_joint` |
| 膝部俯仰（屈伸） | `left_knee_pitch_joint`、`right_knee_pitch_joint` |
| 踝部俯仰 | `left_ankle_pitch_joint`、`right_ankle_pitch_joint` |
| 踝部滚转 | `left_ankle_roll_joint`、`right_ankle_roll_joint` |

`roll`、`pitch`、`yaw` 表示机械参考姿态下的滚转、俯仰、偏航功能。功能参考系由统一 CAD 模板或受控工程记录声明，与交付配置的参考姿态一致。它与第 7.2 节沿运动轴取 +Z 的关节基准不是同一约定；名称不能用于直接填写 `axis` 或决定正负。实际轴线及正向以第 6、7 节为准。

直线运动及特殊机构使用经机械评审的功能名，如 `lift_slide_joint`、`gripper_finger_01_slide_joint`。

刚体内部固定配合不另计运动关节。新建的物理固定连接使用 `<parent>_to_<child>_joint` 或 `<component>_mount_joint`；附加基准的固定连接按生成规则命名并保持唯一。闭环、耦合和多自由度关系按实际连接分别标识，不能为满足命名形式拆改机构。

工具和传感器接口分别使用 `_mount`（安装）、`_tcp`（工作点）、`_optical`（光学）、`_frame`（其他测量基准）。多机器人实例的命名空间前缀只在部署实例化时添加，并保留规范名到实例名的对应关系，不写入通用机械接口。

### 2.4 基准与配合名称

原生对象按下表命名，前缀后完整保留对应接口名。流水线须读取名称及原生所属关系，不从中文文件名推测模型名称。原生前缀允许大写，模型接口名仍按第 2.3 节使用小写。

| 原生对象 | 命名规则 | 示例与派生含义 |
|---|---|---|
| 刚体基准 | `CS_<刚体名>` | `CS_base_link` → `base_link`；`CS_left_forearm_link` → `left_forearm_link` |
| 关节基准 | `JCS_<关节名>` | `JCS_left_elbow_pitch_joint` → `left_elbow_pitch_joint` |
| 命名运动轴 | `AX_<关节名>` | `AX_left_elbow_pitch_joint`；确认轴向与归属，不替代圆柱依据或新增关节 |
| 安装基准 | `CS_<接口名>` | `CS_front_camera_mount` → `front_camera_mount` |
| 工具工作点 | `TCP_<接口名>` | `TCP_left_gripper_tcp` → `left_gripper_tcp` |
| 测量基准 | `SCS_<接口名>` | `SCS_front_camera_optical`、`SCS_torso_imu_frame` |
| 关节配合 | `<关节名>__<约束作用>[_<固定序号>]` | `left_elbow_pitch_joint__coaxial`、`left_elbow_pitch_joint__angle_limit` |

基准固定于正确对象，零件内特征通过实际实例和引用配置定位。新增基准按本表命名；前缀只标识原生载体，导出接口名完整保留前缀后的名称，不改变大小写、删改字符或自动翻译。可复用第 6.2 节规定的唯一机械特征作为轴线依据，无须为前缀增加重复轴线，也不另建有质量的辅助件。

共享零件或子装配的局部基准不固定为单一安装侧。同一件用于左右或多处安装时，在所属装配中按实际实例命名接口基准并引用原有定位特征，如 `CS_left_forearm_link`、`CS_right_forearm_link`；不为区分实例复制制造件或改写共享零件的物料号。

同一关节的同轴、定位和限位配合使用相同关节名前缀；约束作用分别用 `coaxial`、`locate`、`angle_limit`、`distance_limit`，同类约束重复时加固定序号。跨多个关节的耦合按真实关系单独命名，如 `coupling_gripper_sync`，保留原生关联对象，不归到任意一个关节。配合名称仅用于归集和定位，运动类型及自由度仍由完整约束确定。

### 2.5 命名冻结与变更

首版交付前逐项确认所有纳入对象的机械含义、名称、作用域和原生绑定。具有工程含义的接口不能保留 `新建零件`、`配合1`、`坐标系1`、`最终版2` 等默认或临时名；无需用于接口识别的内部建模特征不要求批量改名。

**已发布的模型名称及受控基准沿用原名称。** 不据此批量改写既有硬件的关节、刚体或基准名。CAD 文件显示名变化不能自动改变模型接口名；特征重排、采集顺序及控制编号变化不改变名称或固定序号。

流水线保留本版本的原生对象引用、文档、配置及完整实例路径，并将其绑定到模型实体。跨版本的改名、替换、拆分和合并由受控工程变更记录说明；仅凭同名或采集顺序不能判定为同一对象。模型 ID 不作为跨版本身份登记库。

名称或接口变化按第 3.4 节记录变更关系。纯文件改名保持物料号与模型接口；接口改名、连接对象变化或对象拆并形成新的结构版本，重新核对配合、基准、材料及受控记录。

本版本的派生定义和原生证据须保留实例、刚体、关节两端、基准与模型接口的对应关系。物料号、修订及跨版本接口变化由工程属性或 PDM 变更记录承载，结构负责人在评审时逐项确认。接口变更同时说明受影响的消费者，不建立多级别名链或复制活动关节兼容旧名。

关节清单的结构顺序不代表控制通道顺序；名称映射不能代替拓扑、轴向或零位变化的验收。

## 3. 文件、依赖与版本管理

### 3.1 原生工程目录

一次交付是一份自包含的工程目录，例如：

```text
robot_a/rev_003/
  RA-0001_总装.SLDASM
  assemblies/
    RA-0100_驱动模块.SLDASM
    RA-0200_执行模块.SLDASM
  parts/
    RA-0122_支架.SLDPRT
    RA-0123_输出轴.SLDPRT
  drawings/                  # 使用的原生工程图
    RA-0123_输出轴.SLDDRW
  materials/                 # 使用的自定义材料库
    engineering-materials.sldmat
```

目录组织可沿用工程习惯，文件名支持中文。主装配必须可明确识别，不保留多份候选主装配供流水线猜选。原生工程图、自定义材料库和其他设计依赖按实际使用情况纳入；导出的 URDF、STL 和人工流水线文件不属于结构交付要求。

SolidWorks 原生版本须为[部署指南](deployment.md)列出的受支持版本；其他版本须先完成平台验收。降版或转换后，须重新核验特征、配合、配置及质量属性。仅能查看缓存图形、不能解析实体及工程状态的模式，不属于合格交付。

### 3.2 依赖闭合

- 使用 Pack and Go 或等效原生方式收集主装配、子装配、零件及有效引用，保留可重新解析的关系。
- 从收集后的目录重新打开主装配；原工作目录、共享盘和个人路径不可用时，仍能完整解析交付配置。
- 纳入的虚拟零件和虚拟子装配须另存为真实原生文件，不依赖当前桌面会话。
- 同一文件的不同引用配置必须保留；不能用默认配置替代实例实际使用的配置。
- 外部设计表、方程、上下文引用和库文件影响交付状态时，须内嵌、收集或固化为可重新读取的受控原生结果。
- 不得用替代件、缓存显示或交互查找掩盖缺失依赖。交付目录须与生成输出及运行状态分开。

### 3.3 文件与路径

- 不使用符号链接、Windows junction 或指向包外的工程文件引用。
- 名称不能仅靠大小写区分，如 `Part.SLDPRT` 与 `part.SLDPRT`。
- 不使用 Windows 保留名称，如 `CON`、`NUL`、`COM1`，带扩展名也不允许。
- 文件及目录名称不包含控制字符或 `< > : " \ | ? *`，不能以空格或句点结尾；不将 `.git` 纳入交付。
- 在实际 Windows 路径下验证目录深度和名称长度能被 SolidWorks 正常打开。
- SolidWorks 的 `~$` 锁文件不属于工程版本。

### 3.4 受控版本

几何、配合、配置、基准、材料、限位、零部件替换或交付范围发生变化，必须形成新的结构版本。相同版本不得被不同内容覆写，历史原件及配置必须可重新取得。

变更记录应定位受影响的部件、接口、运动关系和参数。改名、移动、拆分、合并、镜像及实例替换须保留对应关系，使设计变更与纯命名变更可区分。

PDM、Git LFS 或受控目录均可用于留存，须保证版本唯一、原件可取、历史不被覆写。交付后不原地修改已提交版本；后续变更另交一版。文件摘要由系统生成，不能代替工程版本与审批。

## 4. 配置、重建与保存状态

### 4.1 交付配置

主装配必须指定用于交付的配置，明确附件、负载、替代件及各实例的引用配置。交付配置应与声明的机械参考姿态一致，不能将展示、运输或临时装配姿态当作机械零位。

每次交付只指定一个目标配置。同一结构版本可保留多个受控配置，须说明各自用途及差异，分别核验影响几何、运动、质量或接口的内容；不同配置的几何和参数不能混用。

配置级属性与文档级属性冲突时，应在原生工程中消除冲突或明确有效定义。派生配置、简化配置和轻量表示不能改变未声明的结构、运动或质量边界。

### 4.2 原生状态检查

| 检查对象 | 合格状态 |
|---|---|
| 强制重建 | 主装配及必要依赖完成 Force Rebuild，无影响交付的错误 |
| 保存与重开 | 几何、配置、材料、配合和基准已保存；从交付副本重开后状态一致 |
| 解析状态 | 纳入对象完全解析，实体、参考特征和质量属性可读取 |
| 空对象 | 无参与交付的空子装配、丢失实体或未声明的占位件 |
| 实例配置 | 文件及引用配置与设计一致，不依赖零件当前活动配置 |
| 抑制与排除 | 原因、适用配置和交付边界明确，不通过抑制真实运动件消除报错 |
| 隐藏状态 | 仅作为显示设置，不作为质量或模型排除依据 |
| 外部引用 | 无缺失文件、失效上下文、悬空特征或交互查找要求 |
| 配合状态 | 无失败、过定义或非预期自由度；保留真实机构所需的运动 |

欠定义不等于合法运动，完全定义也不等于正确机构。不得为消除提示而临时固定运动件，或放开约束使错误装配能够移动。

## 5. 装配组织、刚体与运动拓扑

### 5.1 刚性连接

刚体是运动中内部相对位姿保持不变的零件集合。装配组织和连接关系必须能确定各实例属于哪个刚体。

- 建议按实际运动模块组织子装配，内部固定连接完整。
- 子装配包含相对运动时，须保留所需自由度；需要在上级装配求解时，使用正确的柔性状态。子装配层级本身不能证明整体刚性。
- 电机、减速器等组件的固定侧与运动侧按真实连接分别归属；简化模型也须保留正确的输出接口与运动关系。
- 同一零件重复安装时，各实例独立识别，不能按文件名合并。
- 每个纳入实例只归属一个刚体，无重复计入或无说明遗漏。紧固件、附件和负载归属明确。
- 多实体零件内部存在相对运动时，应重组为可分别定位的原生实例；不能将运动关系隐藏在单一刚体中。

刚体归属必须由固定连接及原生实例关系唯一确定；零位下暂时不动、实例被设为固定或装配完全定义，均不能单独证明归属。标准装配信息不足时，使用统一 CAD 模板中的原生标记补充必要含义。

### 5.2 连接与自由度

交付模型必须有明确的根刚体，纳入结构与根连通。各运动副连接真实相邻刚体，连接顺序、自由度和驱动／被动属性与设计一致。

串联链从根到末端保留完整连接；中间运动刚体不得合并、遗漏或调换。多自由度机构须保留各独立自由度及相互关系，不能只凭部件名称推断运动轴或顺序。

闭环、并联、齿轮、螺旋及其他联动必须保留真实连接和约束。耦合关系应明确关联对象、传动关系、方向及参考状态。不得为适配某种导出格式删杆、解除耦合、固定被动运动或伪装成独立串联关节。

Release 1.0 的自动提取支持以 `base_link` 为根的树状连接：每个刚体只有一个父级，关节由受支持的配合类型（重合、同轴、距离、平行、垂直、角度、锁定及其限位变体）组合确定，并恰好保留一个相对自由度。闭环、并联、齿轮、螺旋及其他耦合机构不在当前自动提取范围内；此类交付保留真实设计，由流水线明确报告失败并阻断。

柔性变形、间隙和顺应性影响模型用途时，应在原生工程或关联受控记录中明确适用范围。刚体近似不能被当作这些行为已经验证的依据。

## 6. 配合、运动副与轴线

### 6.1 配合要求

| 运动关系 | 必须确定的工程事实 |
|---|---|
| 固定连接 | 无相对运动；安装基准和固定方式明确 |
| 有限转动 | 唯一转轴；除转动外无非预期自由度；工作范围明确 |
| 连续转动 | 唯一转轴；连续运动成立，无未声明的止挡、线缆或传动限制 |
| 直线运动 | 唯一移动方向；无附带旋转或侧向自由度；行程明确 |
| 复合运动 | 实际自由度、约束及耦合关系明确，不强行归为单轴运动 |

必须检查完整配合集合。同轴配合可能仍允许轴向移动，重合面可能保留其他自由度，单个配合名称不能直接等同于运动副类型。

配合选择、对齐方向、引用实体和适用配置须与真实连接一致。临时锁定、接触偶然限制或当前姿态下无法拖动，不构成完整运动约束。

### 6.2 运动轴的几何依据

运动轴须关联真实机械接口，如轴承孔、输出轴或等效圆柱配合面。不得借用远处恰好平行的特征，也不得新增有质量的假几何作为导出辅助。

Release 1.0 的采集路径要求每个运动关节提供可重新读取的圆柱面作为轴线依据（按命名特征或采集记录的特定面解析）；命名基准轴（如 `AX_<关节名>`）与受控记录只用于确认方向、归属和正负，不能替代圆柱依据。缺少可用圆柱面的机构不在当前自动提取范围内：保留真实设计，由流水线明确报告失败，不得改用命名轴、假几何或远处平行特征通过。非圆柱导轨须在原生设计中明确移动方向。

轴线依据必须在正确实例、配置和装配上下文中定位。优先使用稳定命名的圆柱特征；仅在无命名特征时使用采集记录的特定面序号，并在建模变更后重新核验。

各轴之间的相交、平行、异面和偏置关系须与设计尺寸一致。真实轴线和偏置不得为方便导出而调整。几何轴线不自带运动正方向，正负定义见第 7 节。

## 7. 坐标基准、零位与正方向

### 7.1 根基准

根刚体和根坐标系必须明确。采用右手坐标系：X 向前、Y 向左、Z 向上，左右以机器人自身视角定义。无天然前向的设备，须通过安装基准或受控工程图明确前、左、上。

根原点采用设计规定的定位基准，不能默认取 SolidWorks 世界原点、包围盒中心或质心。装配中的临时固定状态不能代替根身份。

### 7.2 刚体、关节与接口基准

每个刚体须提供固定于自身的原生坐标系 `CS_<刚体名>`，根使用 `CS_base_link`。坐标系引用已有设计基准，不重建定位几何。关节、安装接口、工具和传感器基准须明确所属对象；零件内的特征通过实际实例及装配变换定位。

派生关节坐标系采用子刚体坐标系：其原点位于真实运动轴，并通过第 7.3 节的定位基准确定沿轴位置。若另设 `JCS_<关节名>`，须属于该子刚体，并与其 `CS_<刚体名>` 的位置、方向完全一致；已有刚体基准满足要求时，无须重复创建 JCS。安装、TCP 和测量基准可以具有独立偏置，按真实所属刚体派生。

| 定义 | 工程要求 |
|---|---|
| 所属对象 | 明确固定于哪个刚体、运动副或安装接口的哪一侧 |
| 原点 | 由设计定位特征确定完整三维位置 |
| 三轴 | 由受控机械特征确定方向和正负，不仅给出一条无向轴线 |
| 参考状态 | 对应已保存的配置与机械姿态 |
| 名称与引用 | 唯一、稳定、可重新读取，不依赖临时选择或截图 |

所有坐标基准必须正交、单位化且右手，满足 `X × Y = Z`。镜像实例仍须建立右手基准；缩放、镜像矩阵或非正交变换不能代替安装旋转。

关节基准默认采用 +Z 沿正运动轴，X、Y 由机械特征确定并保持右手。沿用其他右手基准时，须通过有向运动轴及受控接口定义明确对应关系，由统一规则转换。

基准按[第 2.4 节](#24-基准与配合名称)命名，复用已有定位基准，不为命名重建几何。名称用于绑定对象，不能代替所属关系和几何定义。基准至导出坐标系的换算由流水线完成，结构组不抄写 XYZ、RPY 或轴向向量。

### 7.3 完整定位

轴线不能确定沿轴位置，平面不能确定面内位置。关节原点须由完整定位基准确定，例如轴线与轴承中面、输出法兰面或规定定位面的交点。

转动基准位于真实转轴，直线运动基准关联真实移动方向与行程参考位置；固定连接按受控安装接口定位。相交轴保留真实交点，异面或偏置轴保留真实距离，不统一套用“几何中心”。

数字模型与派生模型的一致性容差见[质量规范](quality.md#numerical-contract)。该容差不代表制造、配合或装配精度；实物公差按工程图和设计要求执行。

### 7.4 零位与参考姿态

机械零位必须由可重复定位的原生基准、尺寸或配合状态确定。交付配置应保存该零位；若数学零位不可到达，须另行保存可到达参考姿态，并通过原生尺寸或受控定义明确其与零位的偏置。

机械零位、编码器零位和上电回零位须分别定义。不得靠旋转导出坐标系掩盖偏置，也不得将不可到达的数学姿态用于实物验收。

各关节先明确前抬、屈曲、抬升等正运动的机械含义，再确定有向轴。正转遵循该轴的右手定则，直线正向沿该轴。保持其他独立关节在参考姿态，逐关节检查正向运动及连接件、接口的随动；耦合机构按真实联动检查，不能临时解除耦合。

镜像、对称和重复模块须分别确认基准、方向、零位及范围，不能因外形相同直接照抄。零位、方向或传动关系改变后，重新核对全部相关参数。

### 7.5 工具与传感器

- 安装接口与实际工作点 TCP 分别定义，固定于正确刚体，随其真实运动。
- 相机机械安装基准与光学基准分别定义；光学约定为 X 向右、Y 向下、Z 向前。
- IMU 基准对应真实测量轴，保留与安装基准的关系。
- 其他设备按受控接口约定定义方向。无质量基准使用参考几何体，不建立有质量的占位零件。

## 8. 工作范围、干涉与间隙

### 8.1 限位与允许范围

有界运动必须明确上下限及其定位依据。存在机械止挡时，止挡接触几何、基准和尺寸须与范围一致；优先使用对应配置下的原生限位配合表达。

机械硬限位、允许工作范围和安全余量分别定义。限位配合不当然等于控制允许范围；线缆、软管、附件和工艺条件也可能限制运动。

工作范围须有可读取的工程来源：表达该范围的原生配合、统一 CAD 模板中的工程属性或关联受控规格记录。来源须对应本版本、配置、零位和正方向，不以口头说明或无法解析的备注代替。

连续运动必须确实成立。需要回卷、有限线缆寿命或存在局部禁行区时，应保留真实限制；单一上下限不能表达的约束不得丢失。

### 8.2 全行程检查

所有机构均须检查参考姿态、工作范围端点及运动过程，核对连接顺序、实际轴间偏置、接口随动和工作包络。多轴机构还须检查可能产生干涉的组合姿态，不能只检查各轴独立运动。

- 使用干涉检查、间隙验证及必要的原生运动算例，核对运动件与壳体、固定件、附件和负载的关系。
- 不存在未解释的实体干涉或碰撞。过盈配合、设计接触及简模导致的重叠须能定位到对象，具有明确依据和适用范围。
- 最小间隙按设计要求判定，纳入制造与装配公差；理想 CAD 中无重叠不能单独证明实物有足够间隙。
- 检查紧固件突出、线缆与软管的布置、弯曲半径、夹持和缠绕风险。简化为静态外形时，保留相应运动约束及来源。
- 端点检查和离散姿态抽样不能单独证明全行程安全；关键包络须有与用途相符的验证依据。

参考姿态、端点和关键组合姿态应保存在原生配置或运动算例中；既有评审依据通过受控版本关联。

## 9. 驱动、传动规格与单位

### 9.1 零部件身份

关键外购件须保留准确型号、版本和安装关系，包括电机、减速器、丝杠、导轨及轴承等。驱动和传动组件还须明确输出接口，使其能够关联受控规格。仅有近似外观、通用占位名称或电机额定功率，不能确定关节能力。

规格库没有对应记录时，由参数责任人确认规格、适用条件和来源，再建立受控记录。不得根据几何编造速度、力矩或推力。

### 9.2 关节输出能力

| 内容 | 工程要求 |
|---|---|
| 传动关系 | 减速比、导程或机构转换关系及方向明确；效率、损耗和非线性关系须给出采用依据与适用范围 |
| 输出能力 | 明确关节输出侧的允许速度、力矩或推力 |
| 工况 | 区分持续与峰值，明确持续时间、工作制、温度及其他限制 |
| 来源 | 固定到可取得的规格版本，明确原单位和换算依据 |

流水线读取 SI 单位的 `effort`、`velocity`，检查其有限性、正值和派生一致性；传动换算、持续／峰值工况、效率、温度及适用条件由参数责任人在对应受控规格中确认，不由流水线自动推算或验证。

电机 rpm、电流和电机轴力矩不能直接当作关节输出参数。缺少必要规格时明确缺项，不能使用任意大默认值。

### 9.3 单位

| 数量 | 派生模型单位 | 原生工程要求 |
|---|---|---|
| 长度、位置、直线行程 | m | 可用 mm，文档及规格单位准确 |
| 角度、转动行程 | rad | 可用 deg，零位与正方向一致 |
| 质量 | kg | 可用 g，来源和单位明确 |
| 转动／直线速度 | rad/s、m/s | 保留原单位、传动换算和输出侧含义 |
| 力矩／推力 | N·m、N | 对应实际输出，不能用电流代替 |
| 惯量 | kg·m² | 参考点、表达坐标系和惯性积约定明确 |

单位转换由流水线统一完成。不得通过缩放网格、重复换算或改变基准补救原生单位错误。

## 10. 几何与物理属性

### 10.1 几何质量

- 纳入零件具有非空、可读取的真实实体；薄片和柔性简模等例外明确对象、原因及用途。
- 运动轴、轴承接口、安装面、定位特征和关键尺寸保留完整，能够与原生工程图及基准核对。
- 关键运动与安装接口的尺寸、公差和配合要求有明确依据；数字基准与工程图的定位基准一致。
- 不通过隐藏、删除异常零件、修改导出网格或改变单位掩盖设计问题。
- 简化孔洞、外观、内部件或接触面时，明确对质量、连接、工作包络及碰撞的影响。
- 视觉、物理和接触用途分别满足要求；外观正确不能证明质量分布、接触或动态行为正确。

### 10.2 有效物理材料

纳入质量计算的实体必须具有真实物理材料及可信密度，适用配置明确。颜色、纹理、外观和材料名称文本不能代替有效材料赋值。

多实体零件逐个核对实体级与零件级材料，确认实际生效值；不同配置的材料变化分别确认。隐藏对象仍可能参与质量，不以显示状态判断物理边界。

采用的材料库版本、材料条目及密度须可追溯。自定义材料库随目录保留或关联固定受控版本，不依赖接收端同名库的当前值。

### 10.3 物理边界与简化模型

质量范围须与交付配置、附件和负载一致。不得重复计入装配整体与内部零件的质量，也不得遗漏已安装组件。

商业设备简模须具有经确认的物理依据，不能把空壳或包络实体的默认密度当作真实质量分布。单一总质量不足以证明质心和惯量。内部细节可以简化，但须保留安装、运动、物理及碰撞用途所需的事实。

质量、质心或惯量的覆盖值（替代原生计算结果的取值）必须声明来源、适用配置、参考点、坐标系和单位。未说明、来源不清或相互冲突的覆盖值不能作为交付依据；不得调值以获得预期结果。

流水线拒绝生效的质量、质心及惯量覆盖值。受控物理参数须满足完整验收要求，见[质量规范](quality.md#native-definition-verification)。

柔性件、流体、可变负载等无法由静态实体准确表达时，须明确建模边界和适用状态，并关联已有受控参数来源。

薄片、曲面等非实体几何参与质量或惯量计算时，须由声明的厚度与材料、面密度或受控等效参数确定物理属性；碰撞用途另须明确厚度及接触边界。不得因无实体体积默认零质量，也不得任意赋予包络实体密度。

### 10.4 完整物理语义

物理来源必须能确定质量、质心、惯量参考点、表达坐标系和惯性积约定。原生读数或受控参数应保留完整张量，不能删除非对角项或混用关于原点与关于质心的惯量。

检查材料、物理边界、配置及覆盖值的生效状态；核对各模块与整机读数是否符合工程预期。实例变换、单位转换和刚体属性组合由流水线完成，不要求结构组手算或抄写导出张量。

### 10.5 独立工程依据

交付应保留对应配置的整机质量预算、关键外形与接口尺寸及其适用条件。依据来自已有设计预算、原生工程图、受控规格或实测记录，明确附件、负载、原单位及合理不确定度。

原生工程图保留在目录中；PDM、规格库和实测记录通过工程属性关联交付系统可取得、可解析的受控版本。个人路径、不可访问链接和无版本记录不能作为可追溯依据。

本次导出的质量或包围盒不能反向充当独立预算。缺少独立依据时明确缺项，不抄回计算结果或放宽范围代替验收。

## 11. 交付检查与问题闭环

流水线固定为六个阶段：**冻结输入 `freeze` → 解析结构 `discover` → 采集证据 `capture` → 生成 URDF `generate` → 独立验证 `verify` → 提交评审 PR `publish`**。生成输入检查属于 `capture` 的输入质检。每阶段的输入、输入质检、输出与输出质检见[架构设计](design.md#2-how-the-system-works)，并使用同一阶段定义显示在 Airflow 操作界面。

### 11.1 自动检查与工程师确认

下表依据[质量规范](quality.md)划分自动检查与工程确认责任。自动检查以完整输入和合格原生证据为前提；结构负责人在收集后的工程副本中完成工程确认，驱动与实测参数由相应参数责任人确认。

| 检查项 | 自动检查阶段 | 流水线自动覆盖 | 工程师必须检查确认 |
|---|---|---|---|
| 范围与身份 | freeze、discover、verify | 主装配、交付配置及冻结输入文件的绑定；声明身份与产物一致 | 实际产品与结构版本正确，主装配唯一，附件／负载和交付配置符合设计用途 |
| 版本留存 | freeze；衔接在 publish | 文件摘要、版本记录与输入绑定，模型提交的版本衔接 | 历史原件及配置可重新取得，工程变更和审批真实、完整，已交付版本未被覆写 |
| 文件依赖 | freeze、capture、verify | 路径可移植性（Windows 保留名、非法字符、尾部空格／句点、链接、大小写冲突及 `.git`）；包外引用与原生依赖闭合、来源与副本摘要；排除 `~$` 锁文件 | 收集副本脱离原路径后完整打开；实际 Windows 路径深度与长度可用；设计表、上下文和材料库依赖有效 |
| 重建与保存 | capture、verify | 采集副本的原生重建，采集前后原文件未改变 | 设计原件及必要依赖已重建并保存，重开后与评审姿态一致，无影响设计的错误 |
| 配置与实例 | discover、capture、verify | 采集配置一致性、原生实例覆盖及抑制记录 | 各实例引用配置、纳入／排除选择符合实际装配，隐藏未被用作物理排除 |
| 刚体归属 | discover、verify | 实例到刚体的映射完整性，每个实例恰好归属一个刚体，无重复和遗漏 | 实际连接确实刚性，固定侧与运动侧归属正确，未把临时固定或静止姿态当作刚性依据 |
| 拓扑与配合 | discover、verify | 派生关节集合与定义一致，URDF 树的根、连通性和无环性 | CAD 的真实连接、配合、自由度及驱动／被动关系正确，闭环和耦合未被删改 |
| 轴线与基准 | discover、verify | 坐标正交与右手性、CAD 至模型的变换一致性；圆柱轴共线及原点到轴的距离 | 选中的是实际运动接口，原点沿轴位置及轴间偏置有设计依据，根方向与接口约定正确 |
| 零位与正向 | discover、verify | 采集静态姿态的变换一致性，声明的有符号轴在派生定义、模型与 URDF 中一致 | 机械零位可重复，参考姿态及偏置正确；逐关节或按真实耦合检查正向运动和镜像差异 |
| 工作范围 | discover、verify | 已提供限位的数值合法性、上下限顺序及派生一致性 | 硬限位、允许范围、安全余量和线缆约束真实，取值与机械零位及正方向一致 |
| 干涉与间隙 | verify（不支持自动） | **目前未覆盖全行程干涉、碰撞及制造公差验算** | 检查全行程及关键组合姿态、止挡、间隙、附件与线缆，保留设计接触和过盈等例外依据 |
| 工具与传感器 | discover、verify | 已声明附加基准的 CAD 变换及派生连接一致性 | 安装侧、实际 TCP、光学／测量方向正确，基准跟随实际所属刚体 |
| 驱动规格 | discover、verify | 已提供速度、力矩或推力的数值合法性及派生一致性 | 型号、规格版本、传动换算、效率、输出侧和持续／峰值工况正确，由参数责任人确认 |
| 物理属性 | capture、verify | 物理来源完整性及原生质量／质心／惯量覆盖值检测；CAD 物理来源下的材料赋值检查；独立组合物理属性并校验输出 | 材料、密度及库版本符合实际；质量边界、简模及物理参数来源可信，实际分布与适用状态正确 |
| 独立依据 | discover、verify | 导出总质量及整体外形最大尺寸落在已提供的验收区间内 | 区间来自独立设计预算、规格或实测，适用配置和不确定度正确，未反向抄写导出结果 |
| 几何与引用 | generate、verify | 网格覆盖、摘要、非空及退化检查、SI 尺度、实际顶点的 CAD 放置一致性；模型接口名语法、唯一性及实体集合一致性（术语与物料号身份绑定、跨版本改名对应关系不做自动判定） | 原生关键接口、尺寸、公差和简化处理正确；第 2 节的命名、实例身份及引用对象逐项确定，已发布接口保持稳定；跨版本改名、替换、拆分与合并由受控变更记录逐项确认，不建立多级别名链 |

**自动通过只证明记录、计算及派生结果一致，不能独立确认真实刚性、实际自由度、正向运动、机械限位或驱动能力。** 工程师须通过原生配合、基准、配置、运动算例、工程图或受控规格确认这些事实。

第 2 节的接口名、配合归组、原生引用和实例身份由流水线读取并核验。结构负责人确认名称的机械含义及工程变更；不能仅凭名称语法合法或派生集合一致，判定命名及身份正确。

### 11.2 检查报告与 Airflow 展示

报告关联流水线 ID、运行 UUID、结构版本、冻结输入及产物摘要。操作界面逐阶段展示输入、输入质检、输出、输出质检，以及检查标识、记录值、文件摘要和失败诊断；原生发现保留受影响对象与具体问题。修正按第 11.3 节回到工程源。

| 结果 | 状态与含义 |
|---|---|
| 阶段 | 未执行、执行中、完成、失败、上游阻断；只有阶段必需质检通过才可完成 |
| 自动检查 | 通过、失败、未执行；缺少必要证据或前提失败不能判为通过 |
| 未支持检查 | 明确标记“不支持”及覆盖边界，不能当作通过 |
| 工程确认 | 操作界面在相关阶段保留“待确认”；结构负责人在本版本评审 PR 或受控工程记录中完成审批，平台不根据自动通过代签 |

Airflow DAG 文档显示六阶段契约；任务日志记录运行状态及终态逐项检查，`engineering_stages` XCom 保留终态摘要，包括失败。`reports/stages.json` 留存各阶段明细（维护命令的实际执行范围见[操作指南](operations.md#6-independent-review-and-recovery)），`reports/quality.json` 留存独立验算及必需检查清单。

自动检查失败或必需检查未执行，阻断候选模型提交；失败证据保留，后续阶段显示阻断。自动提交 PR 仅形成候选，必要工程确认完成后才可批准模型发布。全行程干涉、公差和实际规格适用性由工程师验收，不能通过删改真实结构规避。

### 11.3 问题闭环

1. 结构负责人完成表中工程师自检，保留本版本的原生工程依据，提交 SolidWorks 目录路径。
2. 流水线执行已支持的自动检查，报告失败、缺项及待工程确认事项。
3. 工程问题回到对应对象、配合、配置、属性或受控记录修正，变更后交付新版本；不修改生成的定义、URDF、网格或报告。
4. 重跑后核对问题已消除；在对应 PR 或受控记录中确认结构版本与交付摘要，保留审批依据。

原生工程合格、模型可加载、运动学一致、仿真、训练和实机控制分别验收。该规范约束结构交付，不代替驱动、标定、接触与动态性能的用途验收。运行和发布流程见[操作指南](operations.md)，模型验收见[质量规范](quality.md)。
