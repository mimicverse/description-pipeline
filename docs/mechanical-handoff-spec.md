# SolidWorks 结构工程与交付规范

本规范只约束结构组在 SolidWorks 中提供的工程内容。结构组交付已保存的总装、零件、依赖及所需原生工程信息；流水线自动生成 `robot.yaml`、版本清单、采集证据、URDF、网格、验收报告和 PR。

结构组不编写流水线配置，不填写运行编号、文件摘要、仓库或分支，不手工导出或修改 URDF。CAD 中缺少或无法单义识别的机械事实必须回到 SolidWorks 补齐，不能通过补写 YAML、猜参数或调整生成结果解决。

本文中的“必须”是工程交付要求，“建议”是推荐做法。工程信息应优先由装配层级、配合、配置、参考几何体、物理材料及已有工程属性表达；仅靠几何无法确定的含义，保留在 SolidWorks 原生属性或受控零部件库中。不得把完整机器人配置换一种文本格式塞入 CAD。

本规范定义目标交付合同，不表示现有工具已能自动读取所有项目。当前能力与待实现项见[部署状态](deployment.md#release-and-deployment-status)；[设计](design.md)说明派生链路，[质量规范](quality.md)说明验收边界。

文中所需原生工程属性和刚体／关节标记由平台 CAD 模板统一定义、验证和发布；不能把尚未发布的模板能力当作 v1.0.0 已有功能。

## 1. 责任与交付边界

| 责任方 | 负责内容 |
|---|---|
| 结构组 | 正确的装配、刚性连接、运动关系、零位、基准、物理材料、机械限位、零部件型号和结构版本 |
| 参数责任人 | 驱动规格、允许速度和输出力矩或推力、适用工况；通过原生工程属性或受控零部件库提供 |
| 平台维护者 | CAD 识别规则、属性模板、零部件库连接、工具、运行环境、硬件路由及发布配置 |
| 流水线 | 收集、冻结、识别、自动生成中间定义、取证、建模、独立验证及候选 PR |
| 模型评审人 | 核对机械含义、异常项和用途；批准模型发布 |

同一事实只维护一个来源。几何位置来自 CAD 特征；运动关系来自装配与配合；物理属性来自有效材料或经认可的物理参数来源。自动生成的文件不是新的人工维护入口。

## 2. 交付目录与文件

### 2.1 交付内容

一次交付是一份自包含的 SolidWorks 工程目录，例如：

```text
M3.0/r3/
  3.0 总装.SLDASM
  parts/
    左前臂.SLDPRT
    左腕.SLDPRT
    ...
  assemblies/
    左臂.SLDASM
    右臂.SLDASM
    ...
  drawings/                  # 有对应受控工程图时保留
    左腕.SLDDRW
  materials/                 # 使用自定义材料库时保留
    robot-materials.sldmat
```

文件名支持中文。目录结构可沿用工程习惯；必须能够明确识别唯一的机器人主装配，其他 `.SLDASM` 是其依赖，不能留下多份含义不明的“最终版”供程序猜选。

交付中不要求 `robot.yaml`、`cad-revision.json`、手工证据文本或导出的 URDF/STL。流水线需要的机器文件、记录及摘要全部自动生成。已有工程图、PDM 记录或零部件库是设计依据，不要求结构组为流水线重新抄写一套。

### 2.2 依赖收集

- 使用 Pack and Go 或等效原生方式收集主装配、子装配和零件，保留可重新解析的引用关系。
- 在收集后的目录中重新打开主装配；原工作目录、共享盘或个人路径不可用时，工程仍须完整解析。
- 纳入的虚拟零件、虚拟子装配必须另存为真实原生文件；不能只存在于当前桌面会话。
- 相同零件引用不同配置时，必须保留对应配置，不能用一份默认配置替代。
- 外部设计表、方程、上下文或库引用影响交付状态时，须内嵌、收集或固化为可重新读取的受控原生结果；不得依赖执行端临时找文件或重新计算个人环境中的数据。
- 交付目录与生成输出、运行状态和模型仓库分开。封存期间不修改源文件；新的修改另交一版。

### 2.3 文件与路径

- 不使用符号链接、Windows junction 或越界引用；不能通过链接把包外文件伪装成包内依赖。
- 名称不能仅靠大小写区分，例如 `Arm.SLDPRT` 与 `arm.SLDPRT`。
- 不使用 Windows 保留名称，如 `CON`、`NUL`、`COM1`，带扩展名也不允许。
- 名称不得包含控制字符、`< > : " \ | ? *`，不能以空格或句点结尾；不把 `.git` 目录纳入交付。
- 在实际 Windows 路径下验证目录深度和名称长度可被 SolidWorks 打开；不要依赖执行端改名修复。
- SolidWorks 的 `~$` 锁文件不属于工程版本，由系统排除。

## 3. 结构版本与工程身份

### 3.1 总装必须明确的信息

以下事实保留在总装工程属性、交付配置或已有 PDM 记录中，具体机器读取键名由平台维护的模板统一提供：

| 信息 | 工程要求 |
|---|---|
| 机型／硬件标识 | 对应稳定产品身份，不能随目录改名而变化；用于系统自动选择模型仓库 |
| 结构版本 | 唯一、不可覆盖，能够重新取得本版本原件 |
| 主装配 | 唯一、明确，不从相似文件名中猜选 |
| 交付配置／零位配置 | 指向实际存在且已保存的准确配置 |
| 上一版本 | 能追溯设计变更关系；首次交付明确为初版 |
| 负责人及变更记录 | 沿用工程属性或 PDM 的责任与变更记录 |

这些是 CAD 工程身份，不是要求结构组手写流水线清单。流水线自动提取身份、生成内容摘要和版本记录。

### 3.2 版本管理

CAD 几何、配置、基准、材料、限位或装配关系发生变化，必须形成新的结构版本。不得以相同版本号替换一套不同 CAD；历史原件、配置和来源须可重新取得。

变更记录应能定位受影响的接口、关节、坐标系和参数。改名、拆分、合并、镜像及左右交换必须明确记录，不能让下游依靠文件时间或“最新”字样判断兼容性。

PDM、Git LFS 或受控目录留存均可，关键是版本唯一、原件可取、历史不被覆盖。流水线的文件摘要证明字节身份，不替代工程版本审批。

## 4. 配置、重建与保存状态

### 4.1 交付配置

主装配必须指定一个用于导出的配置，并明确它就是声明的机械零位。不能依赖打开文档时恰好活动的配置，也不能把展示姿态或运输姿态默认为机器人零位。

交付配置必须明确纳入的附件、负载、电池、电机、紧固件及线束模型。展示配置、替代件或轻量表示不能隐藏应交付的运动部件。

### 4.2 交付前原生检查

| 检查对象 | 合格要求 |
|---|---|
| 强制重建 | 对主装配及必要依赖完成 Force Rebuild；没有影响交付的重建错误 |
| 文件保存 | 几何、配置、材料、配合和参考几何体均已保存；未保存的桌面状态不属于输入 |
| 文档重开 | 从交付副本重开指定配置，结果与设计评审状态一致 |
| 零件解析 | 纳入对象能完全解析，能够读取实体、参考特征及质量属性 |
| 实例配置 | 每个实例引用的文件和配置正确；不能默认读取零件当前活动配置 |
| 抑制状态 | 抑制对象与原因明确；不能靠抑制真实运动件消除报错 |
| 隐藏状态 | 隐藏只影响显示，不代表从质量或机器人中排除 |
| 空对象 | 没有参与交付的空子装配、无几何占位件或丢失实体 |
| 外部引用 | 无交互查找、缺失文件提示或临时替代件依赖 |

应检查欠定义、过定义、配合失败和非预期自由度。不能为了“完全定义”锁死真实关节，也不能把装配松散当作合法运动。

流水线可在独立副本中重建以刷新原生缓存，但不保存覆盖原件，也不替结构组修复设计、配合或零位。

## 5. 装配组织与刚体划分

### 5.1 刚体的工程含义

刚体是运动过程中内部相对位姿保持不变的零件集合。装配组织必须能体现这种连接，而不是只按采购分类、外观或存储方便分组。

- 建议将一个运动刚体组织为独立模块或子装配，内部固定连接完整。
- 同一子装配包含实际运动时，必须保留真实运动自由度及正确的柔性子装配状态；不能把子装配存在本身当作“整体刚体”的证明。
- 电机定子与转子、减速器输入与输出分别归属真实连接的一侧；不能把整套驱动组件无条件并为一个刚体。
- 同一 `.SLDPRT` 多次使用时，实例身份独立，左右或不同安装位置不能按文件名去重。
- 一个实例不能同时属于两个刚体，也不能无说明遗漏。固定附件、紧固件、线束和负载的归属应稳定、明确。
- 多实体零件内部存在相对运动时，须重组为能明确识别的原生零件实例。

### 5.2 可自动识别性

流水线从层级、配合、原生实例身份及必要的 CAD 标记识别刚体，不要求结构组逐项抄写成员清单。工程结构必须使识别结果唯一。

同一零位下“不动”、某对象被 SolidWorks 固定，或装配已经完全定义，都不能单独证明它们属于同一机器人刚体。存在多种解释时，应修正层级、配合或使用平台提供的原生刚体标记；不能让工具用距离或外观猜测。

### 5.3 关节拓扑

机器人应有唯一根刚体和明确、连通的运动链。每个关节连接真实相邻的父、子刚体；父子方向以从机器人根部到末端的机械连接为准。

关节数量、连接顺序和自由度必须与结构设计一致。不得省略中间运动刚体、交换父子、把被动自由度固定，或为了形成树而擅自删杆。

闭环、齿轮／螺旋耦合、联动、柔性变形和并联机构必须保留真实结构。工具没有对应表达及验收能力时应报告不支持，不能把它们伪装成独立树形关节。

## 6. 配合、运动轴与关节类型

### 6.1 配合必须表达真实运动

| 运动关系 | CAD 必须明确的事实 |
|---|---|
| 固定 | 没有相对运动；固定连接和安装基准明确 |
| 有限转动 | 唯一转轴，除转动外无非预期自由度；机械运动范围明确 |
| 连续转动 | 唯一转轴，允许连续旋转；不存在未声明的止挡或线缆限制 |
| 直线运动 | 唯一移动方向；无附带旋转或侧向松动；行程明确 |

使用能够表达真实连接的标准配合和参考几何体。仅有同轴配合可能仍存在轴向移动，仅有重合面也可能保留其他自由度；必须核对完整配合集合，不能把一个配合名称直接等同于关节类型。

关节的真实类型、相邻刚体及剩余自由度须能从 CAD 单义识别。标准配合不足时，使用平台提供的原生工程属性或关节标记补充含义，不通过外部 YAML 描述另一个运动模型。

### 6.2 轴线的几何依据

运动轴必须引用真实机械接口，如轴承孔、输出轴、导轨或受控基准轴。不得借用远处恰好平行的圆柱，也不得为了导出而新增影响质量的假几何。

建议保留稳定命名的基准轴或对应特征。临时面序号不是持久身份；同一文件重开、重建或采集时也可能改变，不能作为工程规范中的唯一轴线依据。

没有可唯一确定轴线的配合圆柱接口时，必须建立稳定命名的原生基准轴或等价受控特征，明确其与导轨、滑动面或实际运动接口的几何关系。直线导轨、燕尾等非圆柱接口不能缺少这项定义；仍无法单义读取时报告 CAD 缺项，不虚构圆柱引用。

圆柱轴线只有几何方向，不能证明关节正方向。轴的正负必须与关节基准和声明的正运动一致，见第 7 节。

## 7. 坐标系、原点、零位与正方向

### 7.1 根坐标系

根坐标系必须由机型安装基准确定，采用右手机体约定：X 向前、Y 向左、Z 向上。左右以机器人自身视角定义。没有天然前向的设备，须在 CAD 基准或受控安装图中明确前、左、上。

根原点使用设计规定的定位基准，不能默认取 SolidWorks 世界原点、包围盒中心或质心。

根基座及其坐标系须明确标识。总装的临时固定状态不能代替根身份；多个固定附件不能被误识别为多个机器人根。

### 7.2 刚体与接口基准

每个运动刚体须有独立、稳定命名且与其固定连接的原生坐标系。坐标系应能在主装配上下文中唯一解析；零件内部的同名特征必须能够通过其真实实例和装配变换定位。

| 内容 | 必须明确的工程定义 |
|---|---|
| 所属对象 | 哪个刚体、关节、工具或安装接口；相对哪一侧固定 |
| 原点 | 由点、圆心、轴线与平面交点、安装面中心等确定完整三维位置 |
| X/Y/Z | 三轴分别依据哪个机械特征，正向指向哪里 |
| 零位 | 对应哪个保存配置与机械姿态 |
| 名称 | 唯一、稳定、可重新读取；不靠临时选择或截图定位 |

所有基准必须正交、单位化且右手，满足 `X × Y = Z`。镜像零件的坐标系仍须保持右手，不能用镜像矩阵、缩放或非正交变换表达安装方向。

可动子刚体的入边关节基准应位于真实运动轴上；固定子刚体按受控安装接口确定基准。基准如何映射到导出 link/joint frame 由流水线统一派生，不要求结构组手填 XYZ、RPY 或轴向向量。

统一关节基准采用 +Z 沿正运动轴，X、Y 由受控机械特征确定并保持右手；不能只确定 Z 而任意旋转另外两轴。已有接口必须采用其他轴约定时，在原生工程属性中明确该约定，由平台规则转换，不能在生成文件中补写一份轴向。

建议命名为 `CS_ROOT`、`CS_<模块>`、`JCS_<关节>`、`TCP_<工具>` 等，使基准类型和机械对象明确。名称可以来自平台 CAD 模板；不能仅靠坐标系存在便推断它属于哪个刚体。

建立基准时：切换交付配置，选定可重建的定位点、轴或面，在 SolidWorks“插入 → 参考几何体 → 坐标系”中选择原点与轴向，命名后显示三轴核对正负及所属对象，重建并保存。不能只保留坐标箭头截图而缺少实际原生特征。

### 7.3 原点不能只给一条轴线

转轴线不能确定沿轴位置，安装面不能确定面内位置。每个关节原点必须具有完整定位依据，例如轴线与轴承中面、输出法兰面或规定定位面的交点。

不能统一使用“几何中心”。相交轴保留真实交点，异面或偏置轴保留真实距离；不得为了坐标整齐强行使腕轴共点。

数字模型的位置、轴线和姿态一致性按[质量规范](quality.md#numerical-contract)验算。0.05 mm、0.05° 等一致性容差不代表制造或装配公差；实物公差仍由工程图和设计要求规定。

### 7.4 零位与正运动

交付配置必须保存声明的机械零位。机械零位、编码器零位和上电回零位不同，应分别识别；不能通过旋转导出坐标系掩盖偏置。

正转按声明的有向轴执行右手定则，直线正向沿声明的有向轴。CAD 基准三轴及正向运动必须一致；不得让流水线从无向圆柱参数猜符号。

每个可动关节应能单独从零位沿正向运动，其他关节保持零位，从而核对末端位置与朝向。零位不在允许范围内时，应明确数学零位与可到达参考姿态，不能把不可到达姿态用于实机验收。

### 7.5 工具与传感器基准

- 安装接口和实际工作点 TCP 分开定义，固定到正确的末端刚体。
- 相机机械安装基准与光学基准分别命名；光学约定采用 X 向右、Y 向下、Z 向前。
- IMU 坐标系对应真实测量轴，并保留与安装基准的关系。
- 附加基准使用原生参考几何体，不为无质量坐标系伪造有质量的零件。

## 8. 限位、驱动规格与单位

### 8.1 机械限位与允许范围

有界运动必须在 CAD 中明确机械止挡及其范围。优先使用对应配置下的原生限位配合；止挡接触几何、基准和尺寸须能互相核对。

必须区分机械硬限位、允许工作范围和安全余量。CAD 配合限制不是当然的控制允许范围；连续旋转也不能忽略线缆、软管、止挡或其他实际限制。

工作范围须有可读取的来源：优先使用确实表达该范围的原生限位配合；线缆、外壳或工艺约束不能由配合表达时，写入平台模板的原生工程属性，或引用可解析的受控规格记录。来源须对应本机型、结构版本、零位与正方向；仅口头说明或无法读取的备注不能补齐范围。

正方向或零位改变后，重新核对整个范围。左右关节分别确认，不能直接照抄同一上下限。

### 8.2 驱动能力的来源

几何不能推算允许速度、力矩或推力。CAD 应保留真实电机、减速器及驱动模块的型号、版本和安装关系，使流水线能够匹配受控零部件库。

没有可匹配的库记录时，由参数责任人将确认的规格及来源写入相应 SolidWorks 原生工程属性。结构组不为流水线另交参数表或 YAML，也不独立编造电控参数。

规格必须对应关节输出侧，说明持续／峰值、减速比、效率、温度或工作制等适用条件。电机 rpm、电流和电机轴力矩不能直接当作关节输出参数。

必要参数或来源缺失时，流水线报告缺项并阻断要求这些参数的交付／用途，不使用“足够大”的默认值。查看几何或运动候选不等于获得可发布的完整 URDF。

### 8.3 单位

| 数量 | 系统采用单位 | CAD 工程要求 |
|---|---|---|
| 长度、位置、直线行程 | m | 原文档可用 mm，但必须保留准确文档单位 |
| 质量 | kg | 原规格可用 g，来源及单位明确 |
| 角度与转动行程 | rad | 原生角度可用 deg，由流水线转换 |
| 转动／直线速度 | rad/s、m/s | 原规格单位、减速换算及输出侧定义明确 |
| 输出力矩／推力 | N·m、N | 不能用电流或未换算的电机轴参数替代 |
| 惯量 | kg·m² | 使用完整张量和明确参考系 |

不得通过缩放导出网格、重复换算或改变坐标系补救单位错误。

## 9. 材料、质量、质心与惯量

### 9.1 有效物理材料

每个纳入实体必须有实际物理材料及可信密度，适用配置明确。颜色、纹理、外观或自定义属性中的材料名称，不能代替 SolidWorks 的有效物理材料赋值。

多实体零件须逐个确认材料，避免实体级与零件级赋值相互覆盖。隐藏件仍可能参与质量；不能仅看显示状态判断质量边界。

### 9.2 质量边界与简模

模型应明确包括哪些电机、减速器、电池、紧固件、线束、负载和附件，避免既计总成又重复计内部零件。

商业设备的空壳简模不能仅靠默认材料密度代表真实质量分布。优先使用经过认可的原生模型和受控物理参数；简化必须保留适用范围。单一总质量不能证明真实质心或惯量。

质量覆盖、质心覆盖及惯量覆盖不得隐式生效。未声明、来源不清或未被工具验收支持的覆盖必须清理；不能依靠覆盖值使结果“看起来合理”。采用受控物理参数时，其来源、适用配置、参考点、坐标系和单位必须可追溯，否则阻断相应用途。

### 9.3 完整物理语义

CAD 与受控参数来源必须能够确定质量、质心、惯量参考点、表达坐标系及惯性积约定。结构组不抄写导出张量、不删除非对角项，也不调节惯量使验收通过。

流水线负责独立组合各实例属性，使用旋转变换和平行轴定理，在 link 基准下计算完整张量，并与整机原生读数核对。其计算正确性不替代材料、简模及实物分布正确性的工程评审。

### 9.4 独立设计范围

应保留本配置的独立整机质量预算、关键外形尺寸及其适用条件，来源可以是总装工程属性、原生工程图、已有设计审批或实测记录。纳入的附件、负载、原单位及合理不确定度明确。

原生工程图保留在交付目录；外部受控记录通过 CAD 属性中的版本引用，由平台从 PDM 或零部件库解析并自动归档采用的记录。不能只留一个平台无法访问的链接、个人路径或未留存版本的引用，也不要求结构组另写证据文件。

流水线从这些受控来源生成验收范围，不要求结构组另写配置。不能抄回本次 CAD 质量、包围盒或导出结果，再放宽范围作为独立验收依据；缺少真正的独立依据时必须报告缺项。

## 10. 几何质量、命名与可识别性

### 10.1 几何质量

- 纳入零件须有真实、非空、可读取的实体或经声明的合法薄片几何。
- 真实运动轴、轴承接口、安装面、定位点及关键尺寸必须保留。
- 不用显示隐藏、手修网格、删除异常零件或改变单位掩盖模型问题。
- 简化外观、孔洞或内部零件时，保留对质量、连接、碰撞和运动范围的影响说明，放在 CAD 注释、工程属性或已有受控设计记录中。
- 视觉、质量、接触和碰撞用途分别评审；视觉简模不能直接证明动态或接触行为。
- 使用非实体薄片、柔性线束等例外时，其对象、原因和适用范围必须能定位到真实 CAD 实例。

### 10.2 命名与实例身份

CAD 名称应表达部位和功能，左右按机器人自身视角定义。建议对模块、关节及基准使用稳定、有意义的名称；避免 `新建零件`、`坐标系1`、`最终版2` 这类无法区分机械含义的名称。

中文 CAD 名称可保留。流水线负责生成符合下游格式的名称和稳定机器身份；结构组不维护一份重复的 URDF 命名清单。语义不明或派生名称冲突时须明确报错，不静默改成另一机械对象。

同一文档的不同实例及不同引用配置分别识别。零件改名、替换、镜像或模块拆分后，应核对关节、基准和受控记录的引用是否仍指向正确对象。

## 11. 腕部及其他多轴机构专项要求

对左右腕和其他紧邻多轴机构，按真实设计逐轴核查，不预设轴数或排列顺序：

| 核查项 | 必须确认 |
|---|---|
| 连接顺序 | 从近端到末端的父子关系正确，中间运动刚体未合并、遗漏或调换 |
| 轴线关系 | 相交、平行或异面关系真实；轴间距离和设计偏置与受控尺寸一致 |
| 原点 | 每轴完整三维定位；沿轴位置有设计依据，不只验证“在轴线上” |
| 正向运动 | 固定其他关节，逐轴正向运动，末端位置与朝向符合真实功能 |
| 左右差异 | 镜像后仍为右手系；符号、零位与范围分别确认 |
| 端点姿态 | 工作范围两端的止挡、间隙、接触及线缆条件正确 |
| 末端随动 | 安装面、工具基准和 TCP 跟随正确的末端刚体 |

不得为了坐标整齐强行让腕轴共点，不从 `roll/pitch/yaw` 名称猜轴线，也不能以整机外观相似替代逐轴确认。

结构组在 CAD 配置、运动状态、参考几何体或已有受控评审记录中保留上述依据；流水线自动采集可读取的姿态和特征，生成审查报告。

## 12. 交付前检查清单

结构负责人从收集后的工程副本完成以下检查，不只验证原工作目录能打开。

| 检查项 | 交付标准 |
|---|---|
| 主装配与身份 | 唯一主装配，硬件、结构版本及配置明确 |
| 版本留存 | 原件可重新取得，本版不覆盖历史，变更关系可追溯 |
| 依赖 | 主装配与所有纳入依赖从交付目录完整解析 |
| 重建与保存 | 指定配置强制重建成功；全部设计变更已保存 |
| 实例与配置 | 纳入、抑制、隐藏及每实例引用配置正确 |
| 刚体 | 内部连接真实刚性；运动件归属正确，无重复和遗漏 |
| 拓扑与自由度 | 关节数量、类型、连接顺序及实际自由度正确 |
| 基准 | 根方向正确；各刚体基准独立稳定，原点完整定位，三轴右手 |
| 零位与正向 | 保存配置对应声明零位；每个关节正运动可独立核对 |
| 限位 | 止挡、工作范围和安全余量明确，左右及零位变更已复核 |
| 驱动标识 | 型号、版本和安装关系足以匹配受控规格；缺项明确 |
| 物理属性 | 有效材料、正确质量边界，无未说明或未支持的覆盖 |
| 独立设计依据 | 整机质量预算、关键尺寸及适用配置可定位，未由本次导出结果反向编造 |
| 几何及例外 | 关键接口完整，简化和薄片等例外有明确用途与依据 |
| 腕部与多轴 | 轴间关系、真实偏置、连接顺序、正向与末端随动逐项正确 |
| 未决项 | 缺失事实没有被默认值、猜测或临时固定掩盖 |

检查通过后，结构组提交该 SolidWorks 目录路径。随后由流水线冻结输入、自动生成机械定义及审查报告；结构组根据报告回到 CAD 修正问题。

## 13. 自动化与验收边界

| 内容 | 流水线职责 | 结构工程职责 |
|---|---|---|
| 文件与版本 | 自动收集、摘要、封存和记录 | 提供正确、已保存、受控且闭合的原生工程 |
| 机器人定义 | 从 CAD 和受控库生成 `robot.yaml` 或等价内部模型 | 使刚体、关节、零位、方向和范围能够单义识别 |
| 几何与物理 | 原生采集、单位转换、质量组合、网格和 URDF 派生 | 确认材料、简模、归属和实际机械含义 |
| 来源与报告 | 自动记录读取位置、原值、版本及检查结果 | 保留原生工程事实及已存在的设计审批依据 |
| PR 与模型发布 | 通过独立门禁后提交候选 PR | 审查机械含义，批准适用用途及模型发布 |

自动识别不意味着从几何猜出全部机器人语义。真实自由度、正方向、零位、范围或物理来源无法确定时，必须产生可定位的 CAD 缺项，不生成伪装完整的配置。

运动学一致、URDF 可加载、仿真可用、训练可用和实机可用是不同结论。干涉、间隙、全行程碰撞、驱动、标定、接触和动态行为分别验收；查看模型或生成候选 PR 不等于这些用途已获批准。
