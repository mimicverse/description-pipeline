# 实现约束

[English](engineering_standard.en.md) · 中文

设计原则与流程见[设计文档](design.md)，输入格式和运行步骤见[运行手册](pipeline.md)。本文用于代码审查。

| 边界 | 要求 |
|---|---|
| 来源适配 | 保存原始读数、修订、配置、完整依赖与稳定身份；处理来源特有语义，不另建消费者生成器。 |
| 规范模型 | 使用 SI，明确变换方向、惯量参考点和表达系；验证实体归属、引用与树结构。固定体融合保持质量、质心和完整张量守恒。 |
| 格式生成 | URDF、MJCF、网格与配置来自同一模型；无法保持语义的约束明确阻断。视觉、碰撞和质量属性分别处理。 |
| 独立验证 | 从原始证据重新计算基准，回读产物并检查实际消费者。列出预期、已查、缺失对象；未知、未运行和失败不能通过。 |
| 构建与发布 | 锁定输入和环境，先生成完整候选再替换交付；中断保留诊断。缓存命中仍须验算，发布时从远端重新取得同一 SHA 并独立验收。 |
| 维护成本 | 一个公共包、一个 CLI；复用通用规则，保留独立物理验算。一台 Windows 或 Linux 完成作者流程，发布不依赖 GitHub Actions。 |

模型与物理用途的能力声明必须有对应证据。夹具回归、安装成功、CAD 可读取、完整原生冻结、
仿真与实机验收分别记录，不相互替代。当前限制集中在[验收状态](validation.md)。
