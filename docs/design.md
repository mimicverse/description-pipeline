# 架构设计

系统将一份原生工程转换为可审查的模型交付。设计围绕三个约束展开：工程事实有明确来源，跨边界结果不可变，验证结论只适用于其绑定的文件与检查范围。

系统保持最小完整形态：一条工作流、一个完整模型、每项规则一个属主。目录对应明确职责，模块边界服务于独立验证和必要副作用；重复入口、并行表示、兼容流程及过渡层随变更移除。文档各自拥有一个职责，直接描述支持的行为。

开发、合并、发行及部署遵循[开发与发行链路](deployment.md#开发与发行链路)。

会话和项目文档的说明正文使用中文。程序界面、API 消息、日志、错误、代码注释、文档字符串及测试描述使用英文；运行时只提供一套英文文案。原生工程的文件名、显示名和原始内容属于输入数据，按原样保留并核验，不因界面语言而翻译或改写。

## 工作流与职责

```mermaid
flowchart LR
  F[冻结输入] --> D[解析结构] --> C[采集证据]
  C --> G[生成 URDF] --> V[独立验证]
  V -->|通过| P[预览与评审 PR]
  V -->|失败| E[诊断与未验证预览]
```

六个阶段及其输入、检查、输出由[系统契约](contracts.md#stages)统一定义。Airflow 调度这些阶段；操作台提交命令和展示结果。两者都不实现机械推导或质量判定。

| 边界 | 职责 | 持有的数据与凭据 |
|---|---|---|
| 浏览器 | 飞书登录、上传、主装配、目标与用途选择、结果与预览 | 用户选择的文件和会话 |
| Linux 平台 | 冻结、推导、生成、验证、报告、发布与持久化 | 原生工程证据、模型仓库和 Git 凭据 |
| Windows 原生执行器 | SolidWorks 原生读取、重建、质量属性读取、网格导出和会话管理 | 临时工程副本、原生任务、资源所有权和传输凭据 |
| 工程评审 | 设计与实物对应、全行程安全、参数真实性和用途批准 | 受控工程记录与对应 PR |

Windows 遵循最小职责原则：只有依赖 Windows/SolidWorks 的操作才在其上执行。它不推导结构，不计算质量闭包，不生成模型或报告，不运行 MuJoCo，不维护产品身份、发布路由或 Git 状态。两端执行同一源码发行版本，使用各自最小依赖集。

冻结检查由 Linux 对照数据库已接纳请求执行，真实检查事件、封存原件和阶段确认沿用同一入口。Windows 接收已冻结工程并从原生发现开始；原生打开失败不能回写成冻结失败。发布路由取自已接纳目标对应的固定配置，触发参数与请求不一致时拒绝执行。

命名采用“原生身份绑定 → 规则规范化 → 统一引用”的单一路径。CAD 名称违规以 warning 反馈并自动修正，不要求先修改 CAD 才能导出；最终 URDF 各部分及其引用严格采用同一规范名称。规则来源于工程命名规范，不从手工导出学习目标名称。

## 数据权威

| 事实 | 权威来源 | 生成物的地位 |
|---|---|---|
| 文档、配置、实例、几何、基准、配合和原生声明 | 已保存的 CAD 与直接原生观察 | 保留来源，不能反写或补造 |
| 工作限位、驱动能力及独立预算 | CAD 工程定义；派生时采用已绑定的适用规则 | 原生与派生分别记录，手工结果不得补值 |
| 名称、方向、坐标及数值修正 | 当前 CAD 对象与读数，以及适用的版本化规则 | 保留原值、规则及结果，显示来源 warning 并独立复算 |
| 产品路由、提交主体、运行身份 | Linux 配置与认证提交 | 只建立行政身份 |
| 规范化模型、URDF、交付网格 | 原生证据经确定规则推导；原生网格是源观察，交付网格是其无损分片与放置 | 待独立验证的声明 |
| 自动质量结论 | 独立验算及实际交付文件 | 绑定主体和检查策略 |
| 工程批准与用途资格 | 工程负责人及对应验收记录 | 平台不推断批准 |

CAD 原始事实与规则派生结果分别保存。允许按明确、可复算的规则规范名称、转换坐标／单位或修正表达；规则可按已证明的 CAD 条件分支。禁止抄用手工导出的值或为匹配结果加入逐对象补丁。派生值须显示 warning；读取失败、冲突及缺少必需工程依据不能靠规则掩盖。认证提交人、内容摘要和平台索引仍不能冒充工程责任、修订或原件控制记录。

原请求由冻结阶段先于生成器封存为 `input/request.json`，后续原字节传递。它是用途的唯一权威，与原生读数共同构成字段来源的独立输入；工程内容身份和发现结果仍是待核对的生成声明。该文件使离线验证能够核对用途、真实配置目标和提交说明，避免生成物互相自证；它只保存不可变证据，接纳、完成与复用资格仍由平台数据库登记，不产生另一份可变业务权威。

工程用途与检查预览用途共用六阶段、规范化模型、独立验证和发布入口。用途不改变原生事实；规则修正、显示／分析策略及其适用条件进入同一版本化规则和来源记录，由生成与独立验证分别复算。分析策略不建立机械范围或实机资格，未知和冲突不能伪装为已知。不增加预览专用模型、验证器或权威文件。具体编码见[用途契约](contracts.md#purpose)。

完整上传、原生选择与完整制备包是不同的清单对象。冻结登记完整上传；原生传输及其后继阶段保留原生选择身份；制备包清单另外核验生成身份和归档原生件。收据投影从对应阶段的既有证据取得绑定，不能把制备包摘要当作原生摘要，也不能为使摘要一致而重写封存观察或改变原始相对路径。具体绑定见[交付格式](contracts.md#delivery)。

平台配置只有不可变快照一个持久化表示。Airflow 连接仅携带快照引用；部署写入、健康检查和运行读取共享该引用的校验与解析边界，不保存端点、路由或秘密的第二份副本。新请求必须绑定当前安装的快照；已接纳请求及其后继阶段保持原配置身份，安装切换不能把它们改路由到新快照。凭据按快照中的受控文件引用读取，轮换不把秘密值写入连接或冻结记录。

执行代码同样只有一个安装来源：活动安装记录中的 DAG 必须是对应发行部署目录内的唯一受管成员，文件摘要与发行清单一致。Airflow 实际配置、已登记版本、序列化文件位置和任务加载来源必须指向该成员；只核验 Python 包或归档文件不能证明实际执行代码一致。运行身份探针只核对这些既有权威，不保存第二份可变调度状态。

## 领域组织

系统是一个模块化应用，部署在一台 Linux 主机与一个串行 Windows 执行端。领域逻辑不依赖 Airflow、HTTP、页面或部署脚本。

| 领域 | 唯一职责 | 允许依赖 |
|---|---|---|
| 契约基础 | 类型、schema、路径、规范序列化、摘要、阶段和判据定义 | 标准库与纯基础算法 |
| 原生适配 | 读取 SolidWorks、绑定实例与会话、封存原始观察 | 契约基础与 Windows API |
| 结构推导 | 原始 CAD 观察转为采集计划 | 契约基础 |
| 生成 | 完整证据转为规范化模型及 URDF/网格 | 契约基础与模型表示 |
| 独立验证 | 从原始证据重建预期并检查实际产物 | 契约基础与独立验证算法 |
| 发布 | 交付重验、Git 提交、PR 确认与幂等恢复 | 契约基础与验证入口 |
| 编排 | 命令、运行、阶段、检查点、资源约束与适配器 | 领域入口 |
| 展示 | 操作台、报告与预览 | 编排查询结果与封存文件 |

推导与验证各自实现机械解释；验证不能导入推导、生成或编排模块，不能借用其模型、缓存、成功标志或期望值。可共享无业务推导的数学原语、格式解析器和契约常量；共享内容本身须有解析、解析解和反例测试。发布调用完整验证入口，禁止另写简化验收。

采集计划只描述要读取的原生对象、选择集合、基准和证据项目，不承担完整机器人模型的第二种表示。完整模型只有一个规范化表示，URDF 是其交付编码。报告与页面由同一结构化结果投影，展示操作没有工程执行副作用。

## 跨主机执行

1. Linux 完成上传、路径准入和不可变冻结，固定主装配、工具版本与提交请求。
2. Windows 接收一次工程副本，在自有 SolidWorks 会话中解析主装配，读取依赖绑定和原始结构观察，封存发现结果并释放会话。
3. Linux 核验原生结果，选择机械解释模式，生成绑定发现摘要的采集计划。
4. Windows 复用同一工程副本，重新建立自有会话，核对计划及实例身份，重建并读取物理属性、轴线和网格，封存完整证据后释放会话。
5. Linux 核验完整传输，生成模型，执行独立验证，并发布候选 PR。

等待 Linux 推导时不占用 CAD 会话。原生执行器串行处理需要 CAD 的操作；传输、Linux 验证与报告不占用 CAD 资源。原生副本在发现与采集之间不得修改或重新上传。

依赖闭包依据 SolidWorks 实际解析的绑定判定。包外、缺失或无法与封存来源绑定的依赖拒绝进入采集。此检查发生在引擎解析之后，不构成操作系统文件访问沙箱；执行主机不向任务暴露无关工程目录或共享盘。

交付配置依据封存原件、原生工作副本的只读状态、读取前后的实际配置及完整重建状态确认。`GetSaveFlag` 描述当前内存文档是否提示保存；配置切换和属性读取也可能置位，不能单独证明原件未保存。原件摘要变化、配置不一致、状态不可读或最终仍需重建时拒绝采集。

内嵌虚拟组件的几何来源是已封存的所属装配，不是它在会话中生成的临时文件。原生读取须同时证明 `IsVirtual=True`、所属装配字节、实例路径、引用配置及当前受控会话中的 `VC~~` 文档；选择、采集和独立验证逐层核对同一绑定。`VC~~` 虚拟组件与 `IC~~` 导入缓存分别记录，均不作为上传文件；路径形状或虚拟标记单独出现不能证明来源。无法建立完整绑定时拒绝采集，不通过复制临时文件补齐输入。

原生声明与配合推导是同一工作流的两种机械解释。声明存在且有效时采用声明；原生读取明确证明声明不存在时才采用配合推导。损坏、不可读或未判定的声明不能触发隐式回退。两种解释的工程边界见[机械规范](mechanical-handoff-spec.md#structure)。

## 持久化与一致性

Linux 的平台数据库是请求、运行、检查点引用、显示元数据和发布意图的唯一可变权威；与 Airflow 元数据库使用同一 PostgreSQL 实例、不同 schema 和权限。Airflow 拥有任务调度状态，平台阶段收据是工程结果权威，页面只读取平台投影。任务成功不能替代工程收据；两者不一致时由编排对账，运行成功要求六阶段收据完整、发布已确认且调度不存在在途操作。

生产调用必须闭合为：认证提交在准入事务中登记请求/运行/派发意图，派发器绑定真实 DAG run，六任务在执行前登记阶段与操作意图，产物封存后登记阶段结果及事件，门户与维护读取数据库投影。禁止从 `meta.json`、`events.json`、目录扫描或文件阶段收据重建另一份业务状态。Windows 的原生操作和 CAD 所有权账本只记录端点已发生事实，由 Linux 对账确认；它们不承担平台运行或发布状态。

维护报告与开关闸门只读取准入与生命周期两个受控视图，在同一只读事务中取得一致快照。对账写端在同一短事务内按已登记身份核验所需的原始 Airflow 任务和 DagRun 事实，仅具有必要列的读取权限，不写调度状态、不建立状态副本。生命周期视图直接关联平台派发意图和真实 Airflow 任务，统一解释活动、终态、未决与未知；不保存第二份调度状态。绑定或源记录缺失仍保留未知对象，权威不可读则拒绝维护操作。调度重试保持同一任务绑定，不能改写已封存的工程终态。

大文件存放在专用文件存储中，以闭合清单与摘要封存。写入临时目录、核验并原子提交后，数据库事务才登记可消费的检查点。崩溃留下的未登记文件不能被下游采用；登记成功的检查点不得覆盖。定期对账恢复未完成调度与外部操作，不依赖网页持续轮询。

新请求、关联运行与初始派发意图在一个短准入事务中登记，与关闭准入共用同一门锁。阶段状态与收据登记在同一事务中；重试使用相同幂等键，发布前登记外部操作意图。数据库事务不跨 HTTP、CAD 或 Git。跨系统一致性由摘要核验、幂等调用、条件写入和事后确认建立。

门户接纳后，DAG 的实际 `freeze` 入口在工程副作用前，用原登记幂等键和真实 Airflow 上下文绑定初始派发意图。逻辑重跑起点与实际入口任务分别记录，不能由前者猜测任务键。DAG、运行及已有绑定必须一致，冲突不能当作幂等成功。已完成冻结的派发缺键由同一原生失败对账事务补齐，重验封存原件和实际调度事实；发现失败已经登记时，还须与原生失败逐项一致，不新增维护入口或改写既有工程结果。

在封存原件中改选主装配复用现有冻结重跑与准入入口：父运行证明原件来源，新请求固定新选择，从冻结执行完整六阶段。页面明确显示本次选择；服务器核对原件清单和请求绑定。原文件无需再次上传，历史请求及检查点不修改，也不增加可绕开平台的手工入口。

数据库不可用时停止业务状态变更，不降级到文件权威。跨文件与数据库提交的崩溃窗口通过原意图和封存清单对账；未登记对象不作为成功检查点，已经登记的完整对象不得因重试覆盖。历史数据迁移按来源可证明范围登记，无法确认的结果保留未决，不通过批量改终态消除维护阻塞。

已登记派发意图缺少任务绑定、或外部已终止而平台仍为排队且没有阶段行，属于同一对账职责。既有 `reconcile` 可在证据充分时补齐原操作的缺失绑定并登记真实结果；不增加旧版专用流程、不复制调度状态、不缩窄生命周期视图或排空门。已知绑定不改写，无法唯一核定的绑定和结果继续保持未知。 冻结失败而后继未运行的请求也由此入口收口：依据实际调度终态和原派发事实结算，保留冻结诊断，不制造原生回执或执行事实。

初始派发由实际冻结入口执行，早期冻结失败时，同一对账事务补齐该任务的真实绑定并将原操作结为失败，不因逻辑重跑起点位于后继阶段就借用后继任务或将它记为未执行取消。阶段、操作和运行的结果须与各自实际事实一致，不能因平台尚未登记开始就把调度已执行的任务当作未执行。

## 资源与失败边界

CAD 资源以端点级独占租约及可核验的进程身份管理。只能访问、关闭或终止自己创建且仍能证明身份的会话；未知会话导致拒绝执行。超时或租约过期只说明需要恢复，不能赋予终止权限。具体规则见[资源契约](contracts.md#resources)。

Linux 不同运行使用独立工作目录。发布按仓库与硬件目标串行；远端变更用显式前置提交与条件更新防护，本地锁不能代替远端校验。

网络错误不证明原生失败，也不触发新 CAD 作业。重连查询同一操作；原生终态失败保留诊断，工程重跑创建新运行并明确复用范围。验证失败阻断发布，发布失败保留已验证交付和所有可确认的外部结果。 定义推导或任务内部异常发生后，只有端点明确证明同一请求的原生作业已失败，才登记该阶段失败并阻断后继；不可达、仍运行或身份冲突保持未知。诊断报告失败不能覆盖原始工程错误或阻止终态登记。

完整恢复规则由[系统契约](contracts.md#recovery)定义。[质量规范](quality.md)定义自动结论与用途边界，[操作指南](operations.md)定义工程师的处理流程，[部署指南](deployment.md)定义平台维护。
