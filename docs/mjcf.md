# URDF → MJCF

本模块消费已经交付的 URDF 与本地网格，生成可携带、可复现、经过独立检查的 MuJoCo 机器人和可选基础场景。它不改变 SolidWorks → URDF 的六阶段契约，不修改上游证据或赋予训练、控制与实机资格。

## 架构与唯一真值

```text
URDF + 引用的 STL ─┐
                  ├─ 冻结输入 → 精确 XML 投影 → MuJoCo 编译
仿真配置 JSON ────┘                              ↓
                         独立读取原 URDF/配置 ← 实际 MJCF 重载
                                                ↓
                                  模型、场景、来源清单、检查报告
```

URDF 是拓扑、关节原点/有向轴/范围、质量、COM、完整惯量和原始几何的唯一来源；上游 CAD 及其证据链仍是这些工程事实的最终来源。本模块不读取另一份规范化机器人 JSON。仿真配置只拥有基座模式、碰撞用途、接触参数、场景和附加标记坐标，不得覆盖机械属性。MJCF 和报告均为可删除重建的派生物。

| 模块 | 唯一职责 |
|---|---|
| `mjcf_contract.py` | 仿真配置、封存清单与数值检查常量；无机械推导 |
| `mjcf.py` | 冻结引用闭包、从 URDF 直接投影 XML、调用完整检查、提交新输出目录 |
| `verification/mjcf.py` | 独立解析冻结 URDF，重载实际 MJCF，数值、配置、资产及来源检查 |
| 现有 `cli.py` | `description mjcf build/check` 的参数与结果呈现 |

不新增通用机器人类、第二份完整模型、插件注册器、任务数据库、调度器或发布器。URDF 树只在一次调用的内存中解析。共用现有规范数值格式、摘要、路径边界和 `runtime.py` 中的 MuJoCo 版本定义及 `requirements/linux-py312.lock`。

直接投影 XML 是必要的有限复杂度：锁定 MuJoCo 的原生 XML 导出会把部分数值缩减至约 6 位有效数字；质量、惯量和坐标保存重载后不能维持本模块的精度要求。投影使用现有可往返 binary64 的数值格式。锁定版 MuJoCo 对 `fullinertia` 的内部主轴分解精度不足以满足本模块的张量检查，因此使用已锁定 NumPy 的 binary64 `eigh` 分解对称张量，写入 `diaginertia` 与右手主轴姿态；特征向量符号和四元数符号规范化，禁止丢弃非对角项。MuJoCo 负责物理编译，独立检查从原 URDF 计算完整张量，并以 `I = R(q)·diag(d)·R(q)ᵀ` 从编译后主惯量与姿态还原实际张量。

## 使用与配置

使用仓库锁定的 Linux / CPython 3.12 / MuJoCo 环境，沿用开发指南的安装方式。

```sh
description mjcf build /path/to/source --urdf urdf/robot.urdf \
  --config /path/to/simulation.json --output /path/to/new-mjcf
description mjcf check /path/to/new-mjcf
```

输入根目录必须包含 URDF 与它引用的全部网格；`--urdf` 是根目录内的相对路径。允许 URDF 通过 `../meshes/` 引用根内资源。拒绝绝对网格路径、远端/`package://` URI、符号链接、路径逃逸、重复或大小写冲突路径。源文件在冻结前后核对摘要，不改写源目录。

配置只支持如下字段；未知键、重复 JSON 键、非有限数字和未知枚举均拒绝。所有影响物理行为的配置都显式提供，不按机器人名称套用默认参数。

```json
{
  "schema_version": 1,
  "base": "floating",
  "collision": {
    "source": "visual_convex",
    "self_collision": true,
    "friction": [0.8, 0.005, 0.0001]
  },
  "simulation": {
    "timestep": 0.001,
    "gravity": [0, 0, -9.81],
    "integrator": "implicitfast"
  },
  "sites": [],
  "floor": {"height": 0, "friction": [0.8, 0.005, 0.0001]}
}
```

`base` 为 `fixed` 或 `floating`；浮动模式只给根刚体添加自由关节，保留根惯量；固定模式用于机械臂、台架或固定基座检查，两种模式共用同一转换入口。机器人零位与 URDF 根坐标一致，不因添加地面自动抬升或修改零姿态。

碰撞来源为 `urdf`、`visual_convex` 或 `none`。`urdf` 只使用原始 collision；`visual_convex` 明确授权将每个 visual 作为独立接触形状，网格由 MuJoCo 使用其凸包；`none` 禁用机器人接触。视觉几何始终不参与接触或惯量推定。不存在自动合并、简化、补碰撞体或重新估计惯量。报告列出实际碰撞数量与来源；无碰撞不能获得接触建模资格。

`self_collision: false` 通过接触位掩码禁用机器人内部接触，仍允许地面接触；`true` 使用 MuJoCo 的标准自碰撞规则，包括其相邻刚体过滤。摩擦依次是滑动、扭转和滚动系数，必须非负，接触维数固定为 3。凸包不是原始凹表面的精确接触表示；使用者需独立验证其对目标任务的适用性。

`sites` 为显式标记列表，每项为 `{"name":"left_sole","link":"left_foot_link","xyz":[0,0,0],"rpy":[0,0,0]}`。位置和姿态相对于指定 URDF link，米/弧度；名称必须唯一，link 必须存在。可表达倾斜足底坐标系，但不按左右脚名称猜测支撑面。site 只是坐标标记，不是传感器。

为保留参考流水线的自动足底能力，可另外给出 `support_sites: [{"name":"left_sole","link":"left_foot_link"}]`；默认空列表。调用方显式指定 link，不依名称猜测。流水线在 URDF 零位从该 link 的接触几何推导标记：`collision.source=urdf` 使用原 collision，`visual_convex` 使用 visual；`none` 或所选 link 无可用三角网格时明确拒绝。自动支撑面目前只接受二进制 STL，其他几何可用显式 `sites`。

在世界 Z 向上、地面水平的约定下，支撑面必须是来自原始三角形且位于所选 link 全部几何下方的平面。共面候选合并，采用接触顶点凸包面积最大的唯一平面；面积并列但平面不同、退化或无解时失败，不取任意面。标记原点取该接触凸包的面积质心，Z 轴为向上法向，X 轴为世界 X 在平面的投影，最后表达回指定 link 坐标。该结果是绑定源几何的派生辅助坐标，不是传感器标定或工程批准。`support_sites` 与 `sites` 的名称不能冲突。判定与容差只有一个机器定义；独立验证从源几何重新验算，禁止导入生成侧支撑算法。

`floor.height` 可为明确数值或 `"supports"`；后者要求非空 `support_sites`，取指定支撑 link 在零位的所选几何的最低世界 Z 值，与参考实现的贴地规则对应。不移动机器人、不改变关节零位。数值 `0` 只表示世界坐标 Z=0，不表示自动贴合足底。

`floor` 可省略，省略时只交付机器人模型；提供时额外生成 `scene.xml`，包含机器人、指定高度的水平地面和一盏灯。地面高度或其源几何推导规则属于场景配置，不改动机器人。`sites`、`support_sites` 可省略，等价于空列表。除此之外，示例中所有字段均必填。没有驱动器、控制器、armature、训练奖励或传感器的隐式生成。

## 支持边界

| 输入 | 行为 |
|---|---|
| 单一根、连通、无环 URDF 树 | 保留全部 link 与关节身份；固定 link 不融合 |
| fixed / revolute / continuous / prismatic | 分别映射固定连接 / 有限 hinge / 无限 hinge / 有限 slide |
| 有限非零有向轴、有限且严格递增的有界范围 | 保留轴向、原点、上下限；轴的幅值规范化为单位向量，原始值仍在冻结 URDF 中保留；拒绝零轴和无效范围 |
| inertial 的任意旋转和非对角惯量 | COM 保留，完整张量旋转到 link 坐标并进行高精度主轴分解；同时写入主惯量与主轴姿态，禁止丢弃非对角信息或自动修复 |
| 正质量与满足物理条件的完整惯量 | 可动刚体必须具备；无惯量的固定坐标 link 保持为无质量 frame，不推定密度 |
| visual/collision 的 box、sphere、cylinder、二进制 STL | 保留坐标、尺度、颜色；单位为 SI；STL 保留原始字节与引用关系 |
| URDF damping / friction | 为保留已声明的被动关节语义，映射关节 damping / frictionloss；不存在时采用 URDF 的零值语义 |
| effort / velocity | 保留在冻结 URDF 与报告中；没有 actuator，不声称实施速度或驱动力限幅；零值与缺失分别报告 |
| mimic、闭环、多自由度、transmission、插件、外部实体、未知扩展 | 拒绝并定位，不静默忽略或近似为固定连接 |

允许的 URDF 元素为 `robot/link/joint/inertial/mass/inertia/origin/parent/child/axis/limit/dynamics/visual/collision/geometry/mesh/box/sphere/cylinder/material/color`；未知扩展不静默忽略。非单位轴仅规范化表示幅值，不改坐标系、轴线或正方向；这不构成机械参数修复。

相同网格的多次实例化保留各实例变换，文件只封存一次。MuJoCo 的网格重心/主轴预处理不改变实例的实际世界几何；检查以补偿后的世界顶点比较。超过锁定消费者所支持限制、网格非有限/空/损坏、负尺度、非物理惯量、未知材质引用都明确失败。

## 交付与可复现性

```text
input/<原根内路径>          # 原始 URDF 及实际引用的网格字节，仅一份
simulation.json            # 原始仿真配置字节
robot.xml                  # 可独立加载的机器人
scene.xml                  # 仅在指定 floor 时生成
manifest.json              # 输入身份、输出文件清单、工具与锁定引擎身份
reports/quality.json       # 独立重算的确定性报告
```

清单覆盖以上除自身和报告外的全部文件；报告绑定清单主体，不形成循环摘要。路径、长度、SHA-256 与实际文件集合必须一致，额外文件也失败。来源只以根内相对路径表示；时间、随机 ID、主机名、临时路径与运行日志不进入确定性产物。两处不同绝对目录、相同输入/配置/工具/引擎必须生成逐字节相同的交付。

只允许生成到新目录，禁止覆盖既有输出或写回源目录。先在独立临时目录完成编译及全量独立检查，再以原子且不覆盖目标的操作提交结果；目标在运行期间被其他操作创建时也必须拒绝。提交前重新核对源文件与配置字节；所有退出路径清理本次临时文件。检查命令只读，检查前后核对主体，独立重算报告并与已保存报告比较。文件、工具、配置或引擎改变后需重新构建。

## 独立验收

验证器不导入转换器，不读取其内存模型或把两个派生文件互相一致当作真值。它从冻结的原始 URDF、网格和配置重建预期；在新进程中使用锁定 MuJoCo 加载实际 `robot.xml` 和可选 `scene.xml`。MuJoCo 加载前先验证生成 XML 的封闭语法及全部资源引用：`robot.xml` 仅允许本模块生成的机器人元素和属性，`scene.xml` 仅允许包含该机器人及约定的地面与灯光。拒绝额外 include、外部资源、默认值覆盖、约束、重力补偿、附加惯量、求解器开关及其他配置未授权的行为；不得让引擎先读取闭包之外的文件。只有身份与输入闭包预检完整通过后才可装载引擎；所有数值比较显式拒绝非有限值。此结构门不取代原始 URDF 与实际编译模型的独立数值比较，语义中性的空白与属性顺序改变仍可接受。每个失败包含检查名与对象，不以成功打开文件代替物理验证。 全部工程验算在该隔离进程内直接读取编译模型，进程边界只交换闭合输入引用和紧凑报告，不序列化、缓存或传回完整引擎模型及网格数组的第二份表示。

| 检查 | 必需内容 |
|---|---|
| 身份与闭包 | 清单、输入、配置、XML、实际网格、引擎版本与报告绑定；未登记文件拒绝 |
| 拓扑与自由度 | link/joint 集合、父子关系、固定 frame、关节类型；浮动基座恰增加 7 个位置量和 6 个速度量 |
| 运动学 | 零位和确定的非零单关节/组合样本；独立 URDF FK 对比实际 MuJoCo link 世界位姿与有向关节轴 |
| 惯性 | 逐 link 质量、COM 和由主轴还原的完整张量；整机质量、COM、平行轴合成张量 |
| 几何 | primitive 尺寸、实例变换、STL 顶点尺度和编译网格变换补偿；视觉/碰撞角色及数量 |
| 关节与配置 | 上下限、连续关节无限位、damping/frictionloss、无隐式 actuator、基座、显式/几何推导 site 与接触位掩码 |
| 场景 | include 的实际机器人、地面高度/法向/摩擦、照明、求解器参数；无自动零位漂移 |
| 运行 | 零状态 forward 与短时零驱动步进无 NaN/Inf；不以短时稳定替代站立、控制或训练资格 |
| 可复现性 | 不同绝对路径的双构建字节相同；保存/重新加载后仍符合全部数值门 |

纯编码/姿态转换比较采用位置、旋转、COM 绝对 `1e-10`，质量与完整张量相对 `1e-10` 加绝对 `1e-12`；STL 为 float32，世界顶点比较采用绝对 `1e-6 m` 加相对 `1e-6`。这些是表示转换精度，不取代 CAD 或物理实测容差。数值常量在 `mjcf_contract.py` 只定义一次，报告记录实际最大残差。

回归必须包含非对角惯量、旋转惯性坐标、非轴对齐有向轴、非对称有界关节、连续/直线/固定关节、固定根与浮动根、重复网格实例、非单位网格尺度、无碰撞输入和显式碰撞来源。负例在重新计算合法清单后故意改错惯量、轴向、父子关系、碰撞或场景，证明独立语义门能拒绝，不能只测摘要失败。

真实机器人在私有工作目录验收，记录源提交/输入哈希、配置、命令、工具身份、逐门结果与限制；不把真实 CAD/硬件数据写进工具仓库。M3 的缺失碰撞、零 effort/velocity 等源事实必须如实保留，不能宣称可驱动或可站立。公共 CI 运行同一完整检查流程的中性合成夹具。

## 精简验收

本模块只保留一个生成入口和一个完整只读检查入口。`rg -n 'generate_mjcf|MjModel|MjSpec|fullinertia|diaginertia|robot\.json' src/description_pipeline/mjcf* src/description_pipeline/verification/mjcf.py` 应能证明：无旧脚本复制、无完整第二模型、无原生低精度 XML 导出链。参考脚本属于另一个仓库，不能声称本 PR 已删除它；本仓库不存在旧 MJCF 实现则删除清单明确记为“不适用”，以实测搜索结果作证。

新增复杂度只为四件事服务：无损物理投影、显式场景来源、可携带引用闭包、独立数值验收。任何额外框架或持久状态必须先证明必要性。
