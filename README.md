# SolidWorks to URDF

将已保存的 SolidWorks 原生工程交付为可追溯、经独立验证的 URDF 模型与评审 PR。

唯一工作流是：**工程文件夹 → Airflow → 独立验证 → URDF 预览与 PR**。机械工程师维护原生设计和工程事实；平台生成模型、证据与报告；工程负责人批准模型的适用用途。

## 使用

1. 按[机械交付规范](docs/mechanical-handoff-spec.md)准备完整、已保存的原生工程。
2. 在操作台通过飞书登录，上传工程文件夹，选择主装配，确认发布目标，选择用途（工程或检查预览）并填写变更说明（必填，可多行）。
3. 查看六个阶段的检查结果，定位并修正源头问题；验证通过后查看实际 URDF、网格与关节限位，进入对应 PR 评审。缺失驱动显示“未提供（未建立驱动能力）”；检查预览的分析窗口标注“检查/预览分析窗口，非机械限位”。

工程师不编写流水线配置，也不手工导出 URDF。完整操作、重跑与问题处理见[操作指南](docs/operations.md)。

## 系统边界

Linux 负责上传冻结、受控规格、结构推导、模型生成、独立验证、报告、预览和发布。Windows 只负责必须通过 SolidWorks/COM 完成的原生读取、重建、测量与网格导出，以及这些操作的安全执行。

每份交付绑定输入、原生证据、工具身份、模型和实际文件。独立验证从原始证据重新建立预期值，并检查交付的 XML、网格与 MuJoCo 加载结果。发布再次核对 Git 中的字节和远端 PR。

验证通过表示[规定检查](docs/quality.md)通过。工程批准、仿真、训练与实机控制分别验收；候选 PR 不赋予这些资格，且绑定所选用途——不同用途的候选与发布恢复身份相互隔离。模型交付包含视觉网格和物理属性，碰撞模型及控制接口由对应用途的工程流程负责。
